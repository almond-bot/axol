Every setting for `axol collect-dagger`. Add any flag below to the command, or set it once in the control panel — see [Command configuration](/cli/configuration) for config files and syntax details.

In the [shared settings file](/guides/control-panel-settings) (`~/.almond/settings.json`, read by default) the same sections appear without this command's wrapper prefixes — `robot_config.axol_config.*` is the file's `axol`, `teleop_config.vr_teleop_config.*` is `teleop`, `teleop_config.kinematics_config.*` is `kinematics`, the other `robot_config.*` fields are `lerobot`, and the recording fields live under `recording` — exactly as for [data collection](/operations/data-collection-config).

```bash
axol collect-dagger --policy_path myorg/pick-act --policy_type act \
  --repo_id myorg/pick-dagger --task "pick up the cup" \
  --robot_config.axol_config.left_stiffness 0.8
```

<Warning>
  Stiffness, gripper torque, `observe_torques`, `observe_cartesian`, `fps`, and the camera set must be the **same as when the policy's data was collected**. A policy only works with the dynamics it was trained on.
</Warning>

## Policy

| Flag | Default | Description |
|---|---|---|
| `--policy_path` | required for local policies | Policy checkpoint — a HuggingFace Hub repo id or local path. Unused for `custom`; model selection stays at the endpoint. |
| `--policy_type` | required | `act`, `smolvla`, `diffusion`, `tdmpc`, `vqbet`, `pi0`, `pi05`, `groot`, or `custom` for the remote custom policy interface. |
| `--device` | `cuda` | `cuda`, `cpu`, or `mps`; local policies only. |
| `--episode_time_s` | `600` | Maximum episode length (s), including interventions. `0` removes the cap. |
| `--policy_max_vel` | `6.283` | Local policies: speed limit (rad/s) on joint actions. `0` disables. |
| `--policy_max_accel` | `21.99` | Local policies: acceleration limit (rad/s²) on joint actions. |
| `--subtasks` | `null` | Local policies: ordered sub-instructions, e.g. `["reach","grasp","lift"]`. Typing `1..N` switches instructions mid-episode. Rejected for custom policies, which manage instructions at the endpoint. |

## Custom policy interface

`--policy_type custom` uses the [custom policy interface](/api/policy-plan).
Set these fields on the DAgger command itself; its shared settings inherit
from `collect-data`, not the run-policy inference category.

| Flag | Default | Description |
|---|---|---|
| `--server_host` | `127.0.0.1` | Address of the existing policy endpoint. |
| `--server_port` | `8765` | Policy endpoint port. |
| `--actions_per_chunk` | `30` | Maximum returned plan horizon. |
| `--plan_config.request_interval` | `5` | Dispatch this many rows between policy requests. |
| `--plan_config.max_adoption_offset_steps` | `6` | Maximum reply age in control steps; must be inside the action horizon. |
| `--plan_config.late_policy` | `blocking_refresh` | Hold and request reset plans on expiry, or choose `abort`. |
| `--hold_to_intervene` | `false` | Must be `true` for custom policies: held grips take control; releasing both requests policy handback. |
| `--shadow_inference` | `true` | Continue prediction during operator control, discarding replies. |
| `--handover_duration_s` | `0.2667` | Joint-space handback ramp after IK, followed by limited convergence. |
| `--record_joint_actions` | `false` | Record resolved joint commands independently of the wire action layout. |
| `--start_from_current_pose` | `false` | Skip startup home and the home after idle teleop. |
| `--home_on_start` | `false` | Restore startup home when current-pose episode starts are enabled. |

## Recording

| Flag | Default | Description |
|---|---|---|
| `--repo_id` | required | Dataset id, `<user>/<dataset>`. |
| `--task` | required | Task description stored with every frame. Sent to local policies; custom policies choose instructions at the endpoint. |
| `--fps` | `30` | Recording rate and the policy state's control rate; must match the policy's training fps. Cameras capture at 60 and are decimated to this before encoding. |
| `--teleop_hz` | `120` | Motor command rate (Hz) while you intervene, independent of `fps`. |
| `--policy_fps` | `20` | Rate the relay feeds the policy's observation frames at, capped at the capture rate. Independent of `fps`: it only thins the RGB ring the control process reads inference images from, so the relay fits beside the headset and panel streams. Between ring frames a tick re-uses the last frame set; the loop, the recorded state rows and the action stream stay at `fps`. |
| `--dataset_resolution` | `SVGA` | Resolution the recorded video is downscaled to, and the resolution the policy sees: `SVGA`, `HD1080`, or `HD1200`. |
| `--vcodec` | per platform | Dataset video codec: `h264` on Jetson, `auto` elsewhere. |
| `--root` | `null` | Local dataset directory. Default is the LeRobot cache, `~/.cache/huggingface/lerobot`. |
| `--push_to_hub` | `false` | Upload the dataset to the HuggingFace Hub when done. |
| `--rerun_ip` | `null` (off) | Stream live visualisation to a [Rerun](https://rerun.io) viewer at this address. |
| `--rerun_port` | `9876` | Rerun viewer port. |
| `--log_level` | `INFO` | `DEBUG`, `INFO`, `WARNING`, or `ERROR`. |
| `--config_path` | — | Load a JSON/YAML config file. Flags override it. |
| `--settings_path` / `--no_settings` | `~/.almond/settings.json` | Read another [shared settings file](/cli/configuration#the-shared-settings-file) / ignore it. Applies beneath `--config_path` and the flags. |
