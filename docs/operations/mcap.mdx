---
title: "MCAP Recording"
description: "Record each episode as an MCAP file with H.265 video, joints, calibration and transforms."
---

Collect data saves a LeRobot dataset by default. Set **Recording format** to `mcap` to save each episode as its own MCAP file instead. Open the files in [Foxglove](https://foxglove.dev), replay them with `ros2 bag`, or read them in Python with the `mcap` and `mcap-ros2-support` packages.

Each file holds:

- every camera's video, encoded to H.265 once on the robot and stored as is;
- each camera's calibration;
- the joints, commands, headset input and, on Jelly, the base;
- the full transform tree, from the base to every camera;
- the episode's task, operator, robot, software version, outcome and calibration ID.

Every sample is stored at its own time, on one clock. Nothing is resampled and no frame is repeated to fill a gap.

## Turn it on

1. In the control panel, open **Settings**, then **Recording**, and set **Recording format** to `mcap`. On the command line, add `--format mcap`.
2. Choose the video size and rate. In **Axol settings**, open **Cameras** and set **Recording resolution**. Set **Recording fps** under **Settings**, then **Recording**. For 1920x1200 at 60 fps, choose `HD1200` and `60`.
3. Set **Streaming resolution** to the **Recording resolution** or higher. Collect data won't start otherwise, because the cameras capture at the streaming size.
4. In the **Collect data** form, type your name in **Operator**. It is saved in every episode and kept for the next session.

MCAP recording works with Collect data on Axol. Mantis, Collect DAgger data and Run policy save LeRobot datasets. **Push to HuggingFace Hub** doesn't apply to MCAP episodes.

## Where the files go

Episodes are saved in the **Dataset root** folder, in a subfolder named after the **Repo ID**: `episode_000000.mcap`, `episode_000001.mcap`, and so on. A new session in the same folder continues the numbering. Use a new **Repo ID** for MCAP recording. Collect data won't write MCAP episodes into a folder that holds a LeRobot dataset.

A file appears only when you save the episode. A discarded take leaves nothing behind.

Plan for storage. Every frame is a keyframe, so each 1920x1200 camera at 60 fps records about 40 Mbit/s. With four cameras that is about 20 MB/s, or 72 GB per hour of recording. Collect data won't start an episode with less than 2 GB free.

## Topics

| Topic | Type | Rate | Contents |
|---|---|---|---|
| `/head/left/video`, `/head/right/video` | `foxglove_msgs/CompressedVideo` | Recording fps | The two eyes of the head camera, H.265. |
| `/wrist/left/video`, `/wrist/right/video` | `foxglove_msgs/CompressedVideo` | Recording fps | The wrist cameras, H.265. |
| `<camera>/camera_info` | `sensor_msgs/CameraInfo` | With every frame | The camera's calibration at the recorded size. |
| `/joint_states` | `sensor_msgs/JointState` | 240 Hz | Measured position, velocity and torque of every joint. |
| `/joint_command` | `sensor_msgs/JointState` | 120 Hz | Joint and gripper targets sent to the arms. |
| `/ee_pose/left`, `/ee_pose/right` | `geometry_msgs/PoseStamped` | 240 Hz | Measured gripper pose, in the `root` frame. |
| `/ee_target/left`, `/ee_target/right` | `geometry_msgs/PoseStamped` | 120 Hz | Commanded gripper pose, in the `root` frame. |
| `/teleop/left/pose`, `/teleop/right/pose` | `geometry_msgs/PoseStamped` | Headset rate | Controller poses as the headset sent them, in the headset's tracking space (`vr_world`). |
| `/teleop/joy` | `sensor_msgs/Joy` | Headset rate | Grips, thumbsticks and buttons. See [Teleop input](#teleop-input). |
| `/base/odom` | `nav_msgs/Odometry` | 50 Hz | Jelly's pose and velocity, worked out from its wheels. |
| `/base/wheel_states` | `sensor_msgs/JointState` | 50 Hz | Jelly's wheel angles (rad, zero at the start of the episode) and speeds. |
| `/base/lift` | `sensor_msgs/JointState` | On change, and once a second | Jelly's lift (`lift`), in metres lowered from fully raised. |
| `/base/cmd_vel` | `geometry_msgs/TwistStamped` | On change | The drive command sent to Jelly. |
| `/tf` | `tf2_msgs/TFMessage` | As measured | Every moving joint: the arms and grippers at 240 Hz, Jelly's base at 50 Hz, the lift when it moves. |
| `/tf_static` | `tf2_msgs/TFMessage` | Once | Every fixed joint, including the camera mounts. |
| `/robot_description` | `std_msgs/String` | Once | The robot's URDF. |

The `/base` topics appear on Axol on Jelly only. Time stamps are Unix time. Each message's log time is its header stamp.

### Joint names

`/joint_states` and `/joint_command` use the URDF's joint names, so the URDF in `/robot_description` places every link.

| Name | Joint |
|---|---|
| `left_s1_0`, `left_s2_0`, `left_s3_0` | Shoulder 1, 2 and 3 |
| `left_e1_0` | Elbow |
| `left_e2_0`, `left_w1_0`, `left_w2_0` | Wrist 1, 2 and 3 |
| `left_gripper` | Gripper opening, from `0` (closed) to `1` (open) |

The right arm uses the same names with `right_`. Positions are in radians, with zero at the rest pose.

### Teleop input

`/teleop/joy` has these axes and buttons, in order:

| | Order |
|---|---|
| Axes | left grip, right grip, left stick x, left stick y, right stick x, right stick y |
| Buttons | left grip button, right grip button, left stick click, right stick click, reset, **A** (stow), left controller tracked, right controller tracked |

## Video

Each frame is one H.265 access unit, encoded on the Jetson as the camera captured it. It is stamped with the time the sensor exposed it. Every frame is a keyframe and carries its own parameter sets, so you can decode from any frame.

The images are the cameras' raw images, without rectification. Undistort them with the `camera_info` on the same topic.

Browser versions of Foxglove play H.265 only on computers with hardware H.265 decoding. The Foxglove desktop app and `ffmpeg` decode it anywhere.

## Calibration

| What | Source |
|---|---|
| Intrinsics (`camera_info`) | Each camera's ZED factory calibration, scaled to the recorded size. The head camera uses `plumb_bob`. A fisheye calibration, as on the wrist cameras, uses `equidistant`. |
| Head stereo baseline | The head camera's factory calibration. It places `head_camera_right_optical` in `/tf_static`. |
| Camera mounts | The URDF's camera frames, from the CAD of the mounts and the cameras. |

The camera mounts are not measured on each robot. The episode's `calibration` metadata records this. If a camera has no factory calibration file on the robot, its `camera_info` is left out and the metadata says `missing`. Open each camera once with the ZED SDK to fetch its file.

## Metadata

Each file has four metadata records.

| Record | Keys |
|---|---|
| `episode` | `index`, `task`, `operator`, `outcome` (`success` or `failure`), `start_time`, `end_time`, `duration_s`, `end_gesture_time` |
| `robot` | `serial`, `model`, `gripper`, `jelly`, `software_version`, `hostname` |
| `recording` | Frame counts, measured frame rate, gaps and missing frames for each camera, joint sample counts, and the clock offset |
| `calibration` | `calibration_id`, `calibration_date`, `calibration_passed`, the source of each part, and each calibration file's name and SHA-256 |

`calibration_id` changes whenever the URDF or a camera's calibration file changes. `calibration_date` is when the ZED SDK saved the newest calibration file on this robot. `calibration_passed` is `not checked`, because the mounts come from CAD.

A camera that drops an exposure leaves a gap, counted in `recording` as `gaps` and `missing_frames`.

## Base odometry

On Axol on Jelly, `/base/odom` gives Jelly's position and heading relative to where it was when the episode started. It also places Jelly in `/tf` (`world` to `jelly`). It is worked out from the wheel angles, so it drifts over distance, mostly when the base turns.

## Check an episode

Run [`axol mcap.check`](/cli/mcap-check) on a file to confirm it has every topic, its frame rates and gaps, and its calibration:

```bash
axol mcap.check ~/.cache/huggingface/lerobot/myorg/pick/episode_000000.mcap
```

It exits with status 1 if something required is missing.
