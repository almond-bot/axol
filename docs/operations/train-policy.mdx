Axol records episodes in the [LeRobot dataset format](/api/lerobot), so you train a policy with standard LeRobot training. Record a dataset with [Data Collection](/operations/data-collection), point LeRobot's training script at it, then run the checkpoint on the robot with [Run Policy](/operations/run-policy).

Any LeRobot training tutorial applies. Use your own dataset's `repo_id` in place of the tutorial's. The links at the end of this page are good places to start.

<Warning>
  Train only on datasets you made or got from a source you trust. Dataset loading is not sandboxed.
</Warning>

## Which policy to train

Start with [**ACT** (Action Chunking with Transformers)](https://huggingface.co/docs/lerobot/en/act). It is small (about 80M parameters), trains in a few hours on one GPU, and often works well with about 50 demonstrations. Once you have a working baseline, you can try larger vision-language-action models such as [SmolVLA](https://huggingface.co/docs/lerobot/en/smolvla).

## Train it

Install the [`lerobot` extra](/advanced/development-install#optional-extras) on a computer with a CUDA GPU. Then train from your dataset's Hub `repo_id`:

```bash
lerobot-train \
  --dataset.repo_id=${HF_USER}/pick-place \
  --policy.type=act \
  --output_dir=outputs/train/act_pick_place \
  --job_name=act_pick_place \
  --policy.device=cuda \
  --wandb.enable=true \
  --policy.repo_id=${HF_USER}/act_pick_place
```

Checkpoints are written under `outputs/train/.../checkpoints`. With `--policy.repo_id`, the trained policy is also uploaded to the Hub, so the robot and any [inference server](/cli/inference-server) can download it. Plan for a few hours for about 100k steps on one GPU.

<Note>
  No GPU? The ACT tutorial links a [Google Colab notebook](https://huggingface.co/docs/lerobot/en/act#train-using-google-colab) for training in the cloud.
</Note>

## Mantis datasets: use `axol mantis.train`

Episodes recorded with the [Mantis](/mantis/hardware) rigs (`axol collect-data --mantis true`) store absolute gripper poses. Each take's frame is set where the operator engaged. A policy trained on these absolute poses learns positions in that one frame, so it doesn't carry over when the robot starts somewhere else.

`axol mantis.train` fixes this. It runs `lerobot-train` with the same flags and checkpoint format, and trains the policy to predict each chunk of actions relative to the pose it starts from. The checkpoint stores this setting, so you run it with `axol run-policy --policy_path <ckpt> ...` as usual.

```bash
axol mantis.train \
  --dataset.repo_id=${HF_USER}/mantis-pick-place \
  --policy.type=act \
  --output_dir=outputs/train/act_mantis_pick_place \
  --job_name=act_mantis_pick_place \
  --policy.device=cuda \
  --wandb.enable=true \
  --policy.repo_id=${HF_USER}/act_mantis_pick_place
```

<Warning>
  Plain `lerobot-train` also runs on a Mantis dataset without errors, but the policy learns fixed positions and doesn't adapt to a different start pose. Use `axol mantis.train` for anything recorded with the rigs. You can also use it on Axol data recorded with `--robot_config.observe_cartesian true` to get the same benefit.
</Warning>

- **Train on your own computer.** `axol mantis.train` refuses remote HF Jobs (`--job.target` other than `local`).
- **Chunk blending is approximate.** Each relative chunk is tied to the pose it was predicted from. Running each chunk from the queue as predicted is exact. `--aggregate_fn temporal_ensemble` in `run-policy` blends overlapping chunks, which works well in practice but is an approximation.

The dataset stays in the standard LeRobot format, so Mantis and on-robot Cartesian episodes can share one dataset.
