Every setting for `axol run-policy`. Add any flag below to the command, or set it once in the control panel — see [Command configuration](/cli/configuration) for config files and syntax details.

In the [shared settings file](/guides/control-panel-settings) (`~/.almond/settings.json`, read by default) `robot_config.axol_config.*` is the file's `axol` section, the other `robot_config.*` fields are `lerobot`, `--left_channel` / `--right_channel` live under `robot`, the recording fields under `recording`, and the inference and action-chunking fields (plus `policy_torque_threshold`) under `inference`.

```bash
axol run-policy --policy_path myorg/pick-act --policy_type act --task "pick up the cup" \
  --robot_config.axol_config.left_stiffness 0.8
```

<Warning>
  Stiffness, gripper torque, `observe_torques`, `observe_cartesian`, `fps`, and the camera set must be the **same as in [Data Collection](/operations/data-collection-config)**. A policy only works with the dynamics it was trained on.
</Warning>

## Policy

| Flag | Default | Description |
|---|---|---|
| `--policy_type` | required | `act`, `smolvla`, `diffusion`, `tdmpc`, `vqbet`, `pi0`, `pi05`, `groot`, or `custom` ([your own model](/operations/custom-policy)). |
| `--policy_path` | required for LeRobot policies | Policy checkpoint — a HuggingFace Hub repo id or local path (reachable from the inference server when remote). Unused for `custom`; model selection stays at the endpoint. |
| `--task` | required | Task description stored with recorded frames. Sent to LeRobot policies; custom policies choose instructions at the endpoint. |
| `--device` | `cuda` | `cuda`, `cpu`, or `mps` (LeRobot policies only). |
| `--episode_time_s` | `120` | Maximum episode length (s). |
| `--fps` | `30` | Control rate. Must match the training fps unless `--allow_fps_mismatch true` (a checkpoint trained on 60 fps data needs `--fps 60`). |
| `--allow_fps_mismatch` | `false` | Start even if `fps` differs from the training fps. Experiments only. |
| `--server_host` | `null` (local) | Address of a remote [`inference-server`](/cli/inference-server). `null` starts one locally for LeRobot policies. With `custom`, connects to an existing endpoint (`null` = this machine); no server is spawned. |
| `--server_port` | `8765` | Inference server port (or your custom policy server's). |

## Action chunking

Custom policies use the [custom policy interface](/api/policy-plan): the endpoint
publishes the final plan, and the robot adopts its remaining rows without
altering that plan. LeRobot policies retain robot-side chunk aggregation.
Execution filtering applies downstream of either path.

| Flag | Default | Description |
|---|---|---|
| `--actions_per_chunk` | `50` | Maximum actions requested from the policy per call. |
| `--plan_config.request_interval` | `10` | Custom policies: dispatch this many rows between requests. |
| `--plan_config.max_adoption_offset_steps` | `6` | Custom policies: maximum reply age in control steps from the saved request origin. Must be inside the action horizon. |
| `--plan_config.late_policy` | `blocking_refresh` | Custom policies: hold and request reset plans on expiry, or select `abort` to fail the session. |
| `--chunk_size_threshold` | `0.9` | LeRobot policies: request the next chunk when the queue drops below this fraction. |
| `--aggregate_fn` | `temporal_ensemble` | LeRobot policies: combine overlapping chunks using `temporal_ensemble`, `weighted_average`, `latest_only`, `average`, or `conservative`. |
| `--temporal_ensemble_coeff` | `0.01` | LeRobot policies: weight decay for `temporal_ensemble`. |
| `--ensemble_blend_s` | `0.2` | LeRobot policies: fade (s) at the end of each chunk so coverage expiry does not step the ensemble. `0` disables. |
| `--align_fade_s` | `1.0` | LeRobot policies: fade (s) over which each new chunk's offset from current motion is blended in. `0` disables. |
| `--exec_max_vel` | `6.283` | Joint speed limit (rad/s) on commands sent to the arms. `0` disables. |
| `--exec_max_accel` | `21.99` | Joint acceleration limit (rad/s²). `0` disables. |

## Recording

Optional — the rollout is recorded to a dataset when `--repo_id` is set.

| Flag | Default | Description |
|---|---|---|
| `--repo_id` | `null` | Dataset id, `<user>/<dataset>`. Set it to record the rollout. |
| `--vcodec` | per platform | Dataset video codec: `h264` on Jetson, `auto` elsewhere. |
| `--root` | `null` | Local dataset directory. Default is the LeRobot cache, `~/.cache/huggingface/lerobot`. |
| `--push_to_hub` | `false` | Upload the dataset to the HuggingFace Hub when done. |
| `--rerun_ip` | `null` (off) | Stream live visualisation to a [Rerun](https://rerun.io) viewer at this address. |
| `--rerun_port` | `9876` | Rerun viewer port. |
| `--log_level` | `INFO` | `DEBUG`, `INFO`, `WARNING`, or `ERROR`. |
| `--config_path` | — | Load a JSON/YAML config file. Flags override it. |
| `--settings_path` / `--no_settings` | `~/.almond/settings.json` | Read another [shared settings file](/cli/configuration#the-shared-settings-file) / ignore it. Applies beneath `--config_path` and the flags. |

## Contact safety

A contact stop trips when a joint's torque is higher than the gravity model expects — the arm hit something. The arms then go limp instead of pushing through.

| Flag | Default | Description |
|---|---|---|
| `--reset_torque_threshold` | `4.0` | Contact stop during return-to-rest (Nm). `0` disables. |
| `--policy_torque_threshold` | `0` (off) | Contact stop while the policy drives (Nm). A trip aborts the episode. The control panel arms it at `16`. |
| `--reset_gravity_comp_kd` | `0.25` | Damping (Nm·s/rad) of the limp hold. |
