title: "Mantis Tracking"
description: "Set up Meta Quest, VIVE Tracker 3.0 or VIVE Ultimate tracking so Mantis can record demonstrations."
---

Mantis **data collection** needs a **pose source**: a tracking system that reports where each rig is. Mantis teleoperation doesn't use tracking. It only drives the grippers from the triggers.

Mantis supports three pose sources. Choose one under **Mantis settings → Tracking** in the control panel. The default is Lighthouse. The choice and its setup are saved on the computer, so every collection run uses them.

| Source | Hardware | How it tracks | What you set up |
|---|---|---|---|
| **Quest** | Meta Quest headset and controllers | The headset tracks the controllers. | Save the controllers' calibration key once. |
| **Lighthouse** | VIVE Tracker 3.0 and 1 to 4 SteamVR base stations | The base stations sweep the room and the trackers sense them. | Install support, pair the trackers, check the base stations, identify the sides and validate tracking. |
| **Ultimate** | VIVE Ultimate Tracker and its wireless dongle | Each tracker follows a room map, with no base stations. | Pair and map once on Windows, then install support, connect the dongle, save the Wi-Fi settings and identify the sides. |

<Note>
  **VIVE Tracker 3.0** is the Lighthouse tracker. **VIVE Ultimate Tracker** is a different HTC tracker that needs no base stations. **Meta Quest** is the headset and its controllers.
</Note>

Before you start, finish the [Mantis hardware setup](/mantis/hardware). The hub must be connected, **Mantis** selected on its tile, the left and right sides checked, and the trigger check passed. Then open **Mantis settings → Tracking** and choose the source. The choice saves right away.

## Set up the source

The **Tracking** tab walks you through each source step by step:

- Each step checks what the computer actually detects.
- **Continue** unlocks when the current step is done.
- If a finished step stops working later, the flow goes back to it.

Data collection won't start until every step is done, even when you start it from the command line. Each step lists the matching CLI command. See the [tracker CLI reference](/cli/tracker) for their flags.

<Tabs>
  <Tab title="Quest">
    The Quest headset tracks its own controllers, so there is nothing to install and no tracker to identify. The headset knows which controller is left and which is right. The only thing to save is the **calibration key**, which names the controller model.
    <Steps>
      <Step title="Source">
        Choose **Quest**. The Quest headset and the computer must be on the same network. You can also use a USB cable instead (see [Quest-over-USB](/guides/quest-over-usb), set up under **General settings → Quest**).
      </Step>
      <Step title="Headset">
        1. Start a Quest bring-up collection run. In the control panel, start **Collect data** with `mantis_allow_uncalibrated` turned on under Advanced. From a terminal, run `axol collect-data --mantis true --mantis_allow_uncalibrated true --repo_id myorg/bringup --task test`. Teleoperation doesn't work for this step.
        2. In the Quest browser, open [axol.almond.bot](https://axol.almond.bot), enter the computer's address and connect. Accept the security certificate the first time.
        3. Choose **Enter VR** and hold both controllers.
        4. The step shows each controller's model. When both match, it shows a **calibration key**, such as `quest:oculus-touch-v3:grip`. Press **Use this key**, then **Save settings**.

        The step is done when the saved key matches both live controllers and ends in `:grip`.
      </Step>
    </Steps>

    Quest 3 Touch Plus controllers in the standard mount have a built-in tracker-to-gripper offset. Other controllers need a measured offset for both sides. See [Transforms](#transforms).
  </Tab>

  <Tab title="Lighthouse">
    Lighthouse tracks two **VIVE Tracker 3.0** units with SteamVR base stations. Before you start:

    - Mount the base stations so they can't move, with the whole Mantis work area in view.
    - Set each **Base Station 2.0** to a different channel.

    <Steps>
      <Step title="Source">
        Choose **Lighthouse**.
      </Step>
      <Step title="Runtime">
        The Axol installer usually installs Lighthouse support for you. If this step is red, press **Install Lighthouse support**. From a terminal, run [`axol tracker.install`](/cli/tracker#axol-trackerinstall). It is safe to run again.

        After you update Axol:

        1. Stop any collection run.
        2. Press **Install Lighthouse support** again, or run `axol tracker.install`.
        3. Restart the service with `sudo systemctl restart axol`.
        4. If you use the **Strict** tracking policy, run **Recalibrate Lighthouse** (see [Validate Lighthouse tracking](#validate-lighthouse-tracking)).
      </Step>
      <Step title="Trackers">
        1. Turn on the base stations.
        2. Pair each tracker. Unplug the tracker from USB so it blinks blue, plug its dongle into the computer, and press **Pair tracker**. From a terminal, run `axol tracker.pair`.
        3. With both trackers on and in view of the base stations, press **Check base stations**. From a terminal, run [`axol tracker.lighthouse.check`](/cli/tracker#axol-trackerlighthousecheck).

        The check listens for about 20 seconds, or up to 150 seconds while it waits for the trackers to report a position. It checks that every base station and tracker is heard. It does not measure tracking quality.

        Under the **Standard** policy, this check also calibrates a new or moved setup. Under **Strict**, it doesn't, so on a new computer run **Recalibrate Lighthouse** first.

        A green tracker light means the tracker is working normally. If only one tracker reports a position, the cause can be tracking or calibration rather than pairing.
      </Step>
      <Step title="Identify sides">
        Press **Identify trackers**. From a terminal, run [`axol tracker.identify --backend survive`](/cli/tracker#axol-trackeridentify). For each side, move **only the rig it asks for** during the 3-second capture. Axol saves each tracker's serial number for its side.
      </Step>
    </Steps>

    When the sides are identified, [validate tracking](#validate-lighthouse-tracking). Validation is required under the **Strict** policy and optional under **Standard**.
  </Tab>

  <Tab title="Ultimate">
    **VIVE Ultimate Trackers** follow a room map that they share over their own Wi-Fi network. They need no base stations or headset. HTC doesn't support Linux, so Axol talks to the trackers' **wireless dongle** through the community [pyvut](https://github.com/nijkah/pyvut) driver. You pair and map the trackers once on a Windows PC. After that, you do everything in the control panel.
    <Steps>
      <Step title="One time on Windows: pair">
        1. On a Windows PC, install SteamVR and turn on its [driver for running without a headset](https://github.com/username223/SteamVRNoHeadset).
        2. Install VIVE Streaming Hub, and install the **VIVE Ultimate Tracker service** inside it. See the [pyvut setup notes](https://github.com/nijkah/pyvut/blob/fcfcd33f4c1f16b0d84f5f741dc1319abdc7942a/README.md#constructing-map-steamvr--vive---only-available-on-windows) and [HTC's pairing guide](https://business.vive.com/us/support/ultimate-tracker/category_howto/pairing-ultimate-tracker-with-the-dongle.html).
        3. Connect the wireless dongle and open **Settings → VIVE Ultimate Tracker → Trackers → Pair new**.
        4. Turn on a tracker and wait until its light is solid blue. Hold Power for about two seconds, until the light flashes blue again, and pair it.
        5. Repeat for the second tracker, on the same dongle.
      </Step>
      <Step title="One time on Windows: map">
        1. Choose **Start setup → Create map** and set the center.
        2. Scan the whole Mantis work area, facing all four directions, from both kneeling and standing height.
        3. Let the map save. Use Refine or Save if they appear.
        4. Turn both trackers off and on again, and check that both find their position and rotation.

        The pairing and the map are stored on the trackers, so they move with the trackers to the robot's computer.
      </Step>
      <Step title="Source">
        In the control panel, choose **Ultimate**.
      </Step>
      <Step title="Runtime">
        Press **Install Ultimate support**, or **Repair Ultimate support** if it is partly installed. From a terminal, run [`axol tracker.ultimate.install`](/cli/tracker#axol-trackerultimateinstall). It is safe to run again. Don't install pyvut yourself with `pip`.
      </Step>
      <Step title="Dongle">
        Plug the same dongle into the computer. The step is done when Axol detects the dongle and can access it. If your user needs to join the `dialout` group, the step shows the command to run. Log out and back in afterward.
      </Step>
      <Step title="Wi-Fi">
        Enter the settings of the Wi-Fi network the trackers share their map over: the network name, password, two-letter country code and center frequency in MHz. This is **not** your office network or the robot's network. The password is hidden after you save it. The settings are saved to `~/.almond/tracker/ultimate_wifi.json` (see the [file format](/cli/tracker#ultimate-wi-fi-file)).
      </Step>
      <Step title="Identify sides">
        Turn on both trackers inside the mapped area and press **Identify trackers**. From a terminal, run [`axol tracker.identify --backend ultimate`](/cli/tracker#axol-trackeridentify). For each side, move only the rig it asks for. Setup is complete when both sides are saved.

        To check the whole setup from a terminal without changing anything, run [`axol tracker.ultimate.check`](/cli/tracker#axol-trackerultimatecheck).
      </Step>
    </Steps>

    <Warning>
      The pyvut driver is unofficial and depends on the tracker firmware. Leave the quaternion order (`wxyz`) and up axis (z-up) at their defaults. Changing either one turns off the built-in tracker-to-gripper offset. Data collection is then blocked until you save a new measured offset or change the setting back. Never change them to correct a mount offset.
    </Warning>

    The standard flat-back mount has a built-in tracker-to-gripper offset, so there is nothing to measure.
  </Tab>
</Tabs>

## Validate Lighthouse tracking

The **Lighthouse tracking quality** card is always shown in the **Tracking** tab for Lighthouse. Use it to choose a tracking policy and check tracking before you collect.

### Choose a tracking policy

In the card, set the number of base stations you installed (1 to 4). Then choose a **Tracking policy**:

| | **Standard** (default) | **Strict** |
|---|---|---|
| Use it for | Portable setups, rooms with two base stations, and first setup. | Fixed installations where the base stations never move. |
| Base station calibration | Keeps improving while you work. | Changes only when you run **Recalibrate Lighthouse**. |
| Before collecting | Validation is optional. | You must pass validation. A pass lasts 12 hours. |
| While collecting | Each take is judged when you save it (see [`--qa_gate`](/operations/data-collection-config)). | Axol watches tracking live. A take with a tracking fault must be recorded again. |

Change the policy only while no operation is running. See [Lighthouse tracking policy](/cli/tracker#lighthouse-tracking-policy) for details.

### Run the check

1. Press **Validate tracking**.
2. Place both rigs **still on the table**, with their trackers in view of the base stations.
3. Wait for the first prompt. Finding the base stations can take **up to two minutes**. Keep both trackers in view, and don't restart the check, or it starts over.
4. Follow the prompts:
   - Hold both rigs still for **5 seconds**.
   - Move both rigs slowly through the work area for **12 seconds**. Move each rig at least **10 cm** and turn its wrist at least **15°**.
   - Hold both rigs still at another working position for **5 seconds**.

The result shows whether the trackers were seen and tracked consistently. It doesn't measure absolute accuracy. You don't need a fixture or measured positions.

Under the **Strict** policy, validate before the first session each day. Collection is blocked if the last check is missing, failed or older than 12 hours, or if the setup changed since. Fix the problem the check reports, then run it again.

### Recalibrate Lighthouse

Run **Recalibrate Lighthouse** if a base station or tripod moved, if the calibration seems wrong, or if **Identify trackers** fails because tracking is unstable. Stop any running operation first.

1. Press **Recalibrate Lighthouse**.
2. Follow the prompts. Rest both rigs at **three different positions and angles** in the work area, **eight seconds** each, with their trackers in view.
3. Complete the hold, move and hold steps of the check, as in [Run the check](#run-the-check).

The new calibration replaces the old one only if the check passes. If it fails, the old calibration stays and the card shows what went wrong.

- If both sides were already identified, a passed recalibration counts as a validation. You don't need to press **Validate tracking** again.
- If the sides were not identified, the card asks you to identify the sides and then validate tracking. Do both before you record.

An error that a base station's identity wasn't received doesn't mean the stations moved. Keep the trackers in view and run the check again.

## Start gesture and recovery

<Tabs>
  <Tab title="Quest">
    To start tracking, hold both rigs at the start pose. **Release both controller grips, then press both grips together.** The controller triggers open and close the grippers. In data collection, **A** starts and confirms a take, the same as on Axol.

    If either controller loses tracking, both sides freeze. Fix the tracking, then release and press both grips again. Tracking never restarts on its own. **Reset** returns to the rest pose and also needs the gesture to start again.
  </Tab>
  <Tab title="Lighthouse / Ultimate">
    A run waits until both trackers report a position and both triggers are sending readings. Then:

    1. Hold both rigs where the session should begin.
    2. **Squeeze both rig triggers together, then release both.** Tracking starts when you release.

    In data collection, the same gesture also starts the take. While recording, quickly squeeze and release either trigger fully **three times** to save the take, or **four times** to discard it.

    If a tracker loses its position or a trigger stops sending readings, both sides freeze. Fix the problem, then repeat the squeeze and release. Tracking never restarts on its own. **Reset** returns to the rest pose and also needs the gesture to start again.

    A Quest headset can still connect to watch the video and status. Its controllers are ignored. By default, the 3D robot overlay is hidden in the headset for these sources.
  </Tab>
</Tabs>

## Transforms

When tracking starts, Axol works out where the rigs are relative to the robot. It still needs to know where the gripper sits relative to the tracker on each rig. This fixed offset is the **tracker-to-gripper transform**.

| Source | Transform |
|---|---|
| Lighthouse (Tracker 3.0) | Built in for the standard flat-back mount: `[0, 0.035, 0.047, 0, 1, 0, 0]` for both sides. The tracker sits 47 mm behind and 35 mm above the gripper motor face. |
| Ultimate | Built in for the standard flat-back mount: `[0, 0.046, 0.047, 0, 1, 0, 0]` for both sides. |
| Quest 3 (Touch Plus) | Built in for `quest:meta-quest-touch-plus:grip`, mirrored between the left and right mounts. The grip point sits 62 mm behind and 45 mm above the gripper motor face. Used when no Quest value is saved. |
| Other Quest controllers | Not built in. Measure the gripper position in each controller's grip frame, and save it for both sides under the controller's `quest:<profile>:grip` key. |

To use a different value, or to save a Quest measurement, edit `~/.almond/mantis/tcp_transform.json`. The control panel doesn't edit this file. For each side, `pos` is the gripper position in the tracker's frame, in **metres**. `quat` is the gripper rotation in that frame, as **`[qx, qy, qz, qw]`**. See [Transform file](/cli/tracker#transform-file) for the full format and how to measure a missing value.

Data collection won't start if either side's transform is missing or out of date.

<Warning>
  Mantis datasets recorded with Axol 0.2.4 or earlier have the gripper rotated about 90°, and Axol can't replay them. Repair them with [`axol migrate-dataset --mantis-tcp-rotation`](/cli/migrate-dataset#mantis-tracker-gripper-rotation) before replay or training.

  Mantis datasets recorded with Axol 0.2.5 to 0.2.16 place the tracker 92 mm in front of the gripper instead of 47 mm behind it. `collect-data` won't add episodes to these datasets. Record to a new `repo_id`.
</Warning>

## Acceptance

Check the setup before you record training data.

**Lighthouse:** pass **Validate tracking** (see [Run the check](#run-the-check)). Under the **Strict** policy, this is required before the first session each day.

**All sources:** run a short bring-up collection run and discard every take. Clear the work area, then start **Collect data** with `mantis_allow_uncalibrated` turned on, or run:

```bash
axol collect-data --mantis true --mantis_allow_uncalibrated true --repo_id myorg/bringup --task test
```

Check these with the real pose source:

1. **Movement.** Left and right are on the correct sides. Motion has the right scale in every direction, wrist rotation follows, and the gripper lines up with the tracker. With Quest, watch the virtual arms in the headset. With Lighthouse or Ultimate, watch the robot view in the control panel.
2. **Recovery.** Cover one tracker, or move it out of tracking, and check that both sides freeze. Restore tracking and check that nothing moves until you repeat the start gesture.

A source that jumps, drifts, swaps sides or doesn't recover cleanly is not ready for collection. `axol teleop --sim --teleop.absolute_mode true` is only a demo of the mapping. Check the real source with Mantis selected, in a collection run.

### Hold the rigs correctly

**Identify trackers** assigns each tracker to a side by which one you move, not by which rig it is on. If the left tracker is on the rig in your right hand, every recorded pose is turned 180° and left and right are swapped.

To catch this, Axol refuses to start tracking when both grippers point away from the robot. This check needs a tracker-to-gripper transform on both sides. The log shows `Teleop engage rejected: both grippers face away from the robot's rest heading`, and nothing is recorded. Swap the rigs between your hands, or identify the trackers again. Then release and squeeze both triggers again.

When you start tracking, hold each rig the way the robot holds its gripper at rest: fingers down, tracker up, handle toward you. A rig pointing straight up or down is not checked.

### During recording

- **Out of reach.** If a rig moves somewhere Axol's arm can't reach, the recording counts those frames as `out_of_reach` and shows a warning. Axol can't follow those poses on replay.
- **Rejected takes.** When you save, Axol checks the take's tracking and camera frames. If it rejects the take, a red alert shows the reason. The alert stays until you start a new recording or save an episode. The saved count goes up only after a successful save.
- **Standard policy.** There are no live tracking checks. Axol judges each take when you save it, on stale poses, frames without tracking and restarts of tracking (see [`--qa_gate`](/operations/data-collection-config)).
- **Strict policy.** The episode controls show the live tracking status. Recording waits until tracking is ready. A warning about reduced coverage still lets you record, but fix the coverage. A serious tracking fault marks the take for a retake and turns off **Save**, even if tracking recovers. You can still discard the take and record it again.

### If tracking fails

| Problem | What to do |
|---|---|
| A tracker was briefly out of view | Restore its view and wait for the live checks to pass, then start a new take. |
| The calibration is wrong | Stop collection and run **Recalibrate Lighthouse**. It includes the validation. |
| The tracking process stopped | Stop the session and read the error. Recalibrating won't fix a crash. Press **Install Lighthouse support** to repair it, and keep the session log if it keeps crashing. |

Smooth poses don't prove that tracking is accurate. Use the acceptance checks above.

## Automatic Lighthouse fault captures

Under the **Strict** policy, Lighthouse collection records tracking data in the background once tracking is ready. The episode panel says that automatic fault capture is ready. You don't need to do anything else.

When a tracking fault happens, Axol saves the 10 seconds before it and the 3 seconds after it. Faults include a pose jump, a stalled pose stream or a timing problem between the two trackers.

1. Keep the session open until the panel says **Tracking diagnostics saved**.
2. Stop the session.
3. Keep the capture shown in the panel and share it with Almond.

Captures are saved under `~/.almond/tracker/diagnostics/fault-*/`. They stay even if you discard the take. A session saves at most three captures, at least 30 seconds apart. Capturing doesn't affect tracking or the grippers.
