Drives the Mantis from **HTC Vive trackers instead of a Quest headset**. A tracker is rigidly mounted where the Quest controller normally sits; `axol tracker.bridge` reads the tracker poses and streams them to the VR WebSocket server as standard `VRFrame` JSON — exactly what a headset sends — so [`teleop --mantis`](/cli/teleop) and [`collect-data --mantis`](/cli/collect-data) run unchanged. In the control panel, **Settings → Mantis** selects Quest, Lighthouse (the default), or Ultimate; the latter two start and stop their matching bridge automatically. The commands below are for direct CLI use and bring-up.

Two tracker families are supported, plus two hardware-free backends for bring-up:

| Backend | Hardware | Tracking | Extra requirements |
|---|---|---|---|
| `survive` | Vive Tracker 3.0 | Lighthouse (outside-in) | 1–2 SteamVR base stations; a libsurvive build on the Jetson |
| `ultimate` | Vive Ultimate Tracker | Inside-out SLAM (no base stations) | The HTC wireless dongle; the `pyvut` package; a one-time map created with VIVE Hub on Windows |
| `static` | None | Arms frozen at a fixed pose | None — the gripper's trigger node is the only live input |
| `synthetic` | None | Generated circular motion | None — for exercising the whole bridge → IK → sim pipeline |

Both hardware-free backends bind their own devices, so they need no `tracker.identify` run.

## Gripper-only bring-up

To bring up or debug a Mantis **gripper** on its own — no trackers, no base stations, no libsurvive — use `--backend static`. The arms hold still and the rig's CAN trigger node is the only thing that can change the commanded state, so a squeeze is unambiguously the cause of any motion you see:

```bash
axol teleop --mantis                  # one terminal (direct CLI use)
axol tracker.bridge --backend static  # another; automatic from the panel
```

Press **Enter** in the bridge terminal to engage, then squeeze the trigger — the gripper should track your squeeze proportionally. Nothing moves before you engage: a disengaged arm freezes its pose *and* its gripper. Prefer `static` over `synthetic` here, since synthetic's orbiting devices keep the commanded arm state changing and muddy the picture.

The absolute (Mantis) IK mode solves the rigid tracker→gripper mount and the world yaw/translation at engage time, so the tracker's own frame conventions never need hand-calibrating — only **gravity alignment and metric scale** must be right, which both tracking systems provide.

## Workflow

```bash
# One-time per tracker family: bind each physical tracker to its rig side.
axol tracker.identify --backend survive   # Lighthouse
axol tracker.identify --backend ultimate

# Direct CLI session: teleop/collection in one terminal and bridge in another.
axol teleop --mantis                # or: axol collect-data --mantis ...
axol tracker.bridge
```

From the control panel, select **Mantis** in the Teleop or Collect Data operation card, then pick **Quest**, **Lighthouse**, or **Ultimate** under **Settings → Mantis**. That dedicated tab also holds the two Mantis camera assignments and tracker binding. Quest connects directly from the headset and starts no bridge. Lighthouse (the default) and Ultimate show their binding status there; press **Identify trackers** for a guided left/right motion capture, with no terminal required. Once bound, they restore their own saved device bindings and start the matching bridge. Plain teleop and data collection engage automatically once both trackers report. There is no manual pause state: **Reset** remains available and tracking resumes automatically afterward. A tracker-lock loss freezes motion until both sides are fresh, then re-anchors and resumes automatically. Mantis is not supported by Collect DAgger or Run Policy. Stopping the operation also stops the bridge.

No tracker→gripper calibration is needed. A Vive Tracker 3.0 on the Mantis rig's standard mount uses the rig's **factory tracker→gripper transform** automatically (a design constant, baked into the SDK) so recorded TCP poses are metrically correct out of the box; a per-unit entry in `~/.almond/mantis/tcp_transform.json` overrides it when present. For everything else, the absolute (Mantis) mapping absorbs the rigid mount offset — along with the world yaw/translation — into the engage snapshot, so holding the grippers at the agreed start pose and engaging **is** the alignment act. Alignment quality at engage bounds the episode's absolute accuracy either way.

Until the rig's button PCB lands, the bridge's terminal is the engage/reset control surface: **Enter** toggles engage (the alignment squeeze of the Quest flow — hold both grippers at the robot's rest pose relative to the scene first), **r** returns to rest, **q** quits. Gripper commands come from the rig's CAN trigger node, which defaults to that side's Mantis gripper bus (override with `--trigger-can-left` / `--trigger-can-right`): the analog trigger tracks your squeeze proportionally, closing the gripper as you pull and opening it as you release. During data collection, rapidly fully squeeze and release either trigger **three times** to start a take; repeat the triple press while recording to end and save it as a success. **Four** rapid presses ends and saves the take as a failure. The triple-press action waits briefly after its third press so a fourth press can select failure. A side whose trigger node can't be reached — no such CAN interface, bus not brought up, or `null` in the config — streams fully open and logs a warning.

## `axol tracker.bridge`

| Flag | Description |
|---|---|
| `--backend {survive,ultimate,synthetic}` | Tracker backend. Default: the saved config (`~/.almond/tracker/config.json`), else `survive`. `synthetic` streams generated motion for end-to-end tests without hardware. |
| `--left KEY` / `--right KEY` | Override the saved device binding (libsurvive codename like `T20`, or an Ultimate tracker MAC). |
| `--host HOST` | VR server host — the machine running teleop/collect-data. Default: `localhost`. |
| `--port INT` | VR server port. Default: 8000. |
| `--hz FLOAT` | Frame streaming rate. Default: 120. |
| `--trigger-can-left IFACE` / `--trigger-can-right IFACE` | SocketCAN interface of that side's trigger node; overrides the saved config, which defaults to `can_mantis_l` / `can_mantis_r`. The node publishes its analog trigger position at 100 Hz on CAN ID `0x009`. |

A side whose tracker loses tracking (occlusion, SLAM relocalising) holds its last good pose and logs a warning rather than feeding IK a glitch. A control-panel-managed bridge automatically freezes motion, waits for both trackers to become fresh, then re-anchors and resumes; the standalone bridge retains its manual Enter-to-toggle behavior. A stale trigger node (no frames for ~250 ms — unpowered or disconnected) likewise holds the last grip command rather than jumping, and the bridge logs the dropout.

## `axol tracker.identify`

The control panel's **Identify trackers** button runs this command on the serve host. For terminal use, it discovers the powered-on trackers, then asks you to move each rig in turn; the device with the most motion is bound to that side. Bindings are retained separately for Lighthouse and Ultimate so the panel can switch between them. Saves `~/.almond/tracker/config.json`:

```json
{
  "backend": "survive",
  "left": "T20",
  "right": "T21",
  "bindings": {
    "survive": {"left": "T20", "right": "T21"},
    "ultimate": {"left": "A1:B2:C3", "right": "D4:E5:F6"}
  },
  "ultimate_quat_order": "xyzw",
  "ultimate_up_axis": "z"
}
```

| Flag | Description |
|---|---|
| `--backend {survive,ultimate,synthetic}` | Backend to use and save. Default: the saved config, else `survive`. |

## `axol tracker.install` / Vive Tracker 3.0 setup

`axol provision` installs a pinned [libsurvive](https://github.com/collabora/libsurvive) build automatically. For direct CLI repair, run:

```bash
axol tracker.install
```

The command installs build dependencies, builds `survive-cli` with Eigen and the native Linux libusb backend (not OpenBLAS or HIDAPI), installs the Vive udev rule, and is safe to rerun. The libusb backend is required for `survive-cli --pair-device 1` to pair a tracker with its HTC dongle. Then mount 1–2 SteamVR base stations (1.0 or 2.0) with the workspace in view and connect each tracker over USB-C or its HTC dongle.

Pairing and left/right assignment are both available in **Settings → Mantis**. Use **Pair tracker** once for each tracker/dongle pair (the tracker must be unplugged from USB and blinking blue), then use **Identify trackers** to move each Mantis and save its side assignment. The equivalent pairing command is `axol tracker.pair`.

For a manual fallback, use the same upstream source:

```bash
sudo apt install build-essential cmake zlib1g-dev libx11-dev libusb-1.0-0-dev \
                 freeglut3-dev liblapacke-dev libhidapi-dev libudev-dev
git clone https://github.com/collabora/libsurvive.git && cd libsurvive
# udev rules so the trackers are readable without root
sudo cp ./useful_files/81-vive.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
cmake -B build -DUSE_HIDAPI=OFF -DUSE_EIGEN=ON -DUSE_OPENBLAS=OFF && cmake --build build -j
sudo cmake --install build
# optional, preferred: the Python bindings (the bridge falls back to
# parsing a survive-cli subprocess when these aren't importable)
uv pip install ./bindings/python
```

<Note>
  On ARM, avoid linking libsurvive against OpenBLAS (known instability/CPU blowups); `-DUSE_EIGEN=ON` sidesteps it. Close SteamVR if one is somehow present — it competes for the devices.
</Note>

libsurvive calibrates the base-station world on first run (leave the trackers still and visible for a few seconds); the resulting world frame is shared by all trackers and gravity-aligned.

## Vive Ultimate Tracker setup (dongle + pyvut)

There is no official Linux support; the bridge uses the community [pyvut](https://github.com/nijkah/pyvut) driver, which speaks to the **wireless dongle over USB HID** without a headset:

1. **One-time, on Windows:** create the SLAM map with VIVE Hub (Streaming Hub) — pair the trackers to the dongle and walk the map-creation flow (the final "connect a headset" step can be ignored). The map is stored on the trackers and shared between them.
2. On the Jetson: `sudo apt install libhidapi-hidraw0 libhidapi-libusb0`, then install `pyvut` into the project environment (`uv pip install git+https://github.com/nijkah/pyvut`). Add a udev rule (or `chmod` the `/dev/hidraw*` node) so the dongle is readable without root.
3. Plug the dongle in and run `axol tracker.identify --backend ultimate`.

<Warning>
  The dongle protocol is reverse-engineered and firmware-dependent. At first bring-up, verify the pose conventions: hold a tracker still and level and check the streamed orientation is gravity-upright. If it isn't, flip `ultimate_quat_order` (`xyzw`/`wxyz`) and/or `ultimate_up_axis` (`z`/`y`) in `~/.almond/tracker/config.json`.
</Warning>

The factory tracker→TCP constant is still TODO. Its physical datum is the center of the tracker's bottom mounting surface on the 1/4-20 insert axis (the seating plane at the screw center); derive the vector from that point to the gripper TCP and the tracker→gripper rotation from the mount CAD, then verify the pyvut axes and URDF overlay on the bench.

## Acceptance check

After mounting and binding, run `axol teleop --sim` with the bridge streaming: engage, move each rig slowly, and confirm the sim arms follow smoothly with no jumps or drift. A tracker that stutters or relocalises here will not produce usable Mantis data.
