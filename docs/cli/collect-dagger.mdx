title: "collect-dagger"
description: "DAgger data collection: a trained policy drives while the operator intervenes from VR, and both are recorded."
---

Runs a trained policy on the robot while the operator watches in VR and steps in to correct it. The whole session is recorded to a [LeRobot](https://github.com/huggingface/lerobot)-format dataset, both the policy's motion and the operator's corrections. This is the [DAgger](https://arxiv.org/abs/1011.0686) loop: you record demonstrations where the policy struggles, so retraining fixes those failures.

Local policies run inference on the robot, one action per control tick. [Remote policies](#remote-policies-through-the-custom-policy-interface) run on a desktop. Cameras and recording work as in [`collect-data`](/cli/collect-data).

<Warning>
  Load only policy checkpoints and resumed datasets that you created or
  obtained from a trusted source. Loading them is not sandboxed.
</Warning>

With a local policy, the VR grip buttons control interventions during an episode:

- While the policy drives, **either grip alone** freezes it. The robot holds its pose and recording pauses.
- **Both grips** hand control to you. Teleop engages at the robot's current pose and recording resumes.
- **Either grip alone** hands control back to the policy.

Nothing is recorded while frozen, so the dataset goes straight from the policy's motion into your correction. Remote policies use [hold-to-intervene controls](#remote-policies-through-the-custom-policy-interface). In both modes, rows you drive are tagged with LeRobot's per-frame `intervention` flag.

Episodes start and end as in `collect-data`:

- Press the **record** button to start an episode. The policy starts driving and recording begins.
- Press **record** again to save.
- Press **record** with **reset** held to discard and record again.

On the terminal, `s` saves, `r` discards, and `q` discards and quits. `--episode_time_s` saves the episode if nothing is pressed in time. With a local policy and `--subtasks`, type a number from `1` to `N` to switch the policy's instruction without ending the episode.

<Tip>
  For the end-to-end workflow, from a trained checkpoint to recorded corrections, see the [DAgger Collection guide](/operations/dagger).
</Tip>

This command is configured through draccus. Local inference uses `--policy_path`, `--policy_type` and `--device`. `--policy_type custom` selects the [custom policy interface](/api/policy-plan). The recording side matches [`collect-data`](/cli/collect-data): the nested `robot_config` and `teleop_config` set cameras, per-joint gains, IK and the VR server. See [Command configuration](/cli/configuration) for the syntax and [DAgger Collection Config Parameters](/operations/dagger-config) for every setting.

| Flag | Description |
|---|---|
| `--policy_path PATH_OR_REPO` | Local checkpoint path or HuggingFace repo ID. Required for local policies, unused for `custom`. |
| `--policy_type {act,smolvla,diffusion,tdmpc,vqbet,pi0,pi05,groot,custom}` | Local policy architecture, or `custom` for a remote endpoint (required) |
| `--task TEXT` | Natural language task description recorded with the dataset (required) |
| `--repo_id <user>/<dataset>` | Dataset repo ID to record to (required). Point it at an existing dataset to resume it, as in [`collect-data`](/cli/collect-data). |
| `--subtasks '["step one", "step two"]'` | Local policies only: ordered per-step instructions, as one inline list. The dataset's task string stays `--task`. Default: none |
| `--episode_time_s INT` | Longest episode in seconds before it saves (default: 600). `0` removes the limit. |
| `--fps INT` | Policy and recording frame rate (default: 30). Must match the policy's training rate, and can't exceed the camera rate. |
| `--teleop_hz INT` | Motor command rate while you drive (default: 120). The policy and frozen states always run at `--fps`. |
| `--policy_fps INT` | Rate of camera frames for the policy's observations (default: 20). The dataset still records every frame at `--fps`. |
| `--policy_max_vel FLOAT` | Local policies only: per-joint velocity limit (rad/s) on the policy's arm actions (default: 6.2832, 2π). `0` turns it off. |
| `--policy_max_accel FLOAT` | Local policies only: per-joint acceleration limit (rad/s²) on the policy's arm actions (default: 21.9911, 7π) |
| `--device STR` | PyTorch device for local inference (default: `cuda`). Use `cpu` with the hosted Jetson install, which has CPU-only PyTorch. |
| `--dataset_resolution {SVGA,HD1080,HD1200}` | Resolution of the dataset video and of the policy's images (default: `SVGA`, 960×600). A resumed dataset keeps its original resolution. |
| `--vcodec STR` | Dataset video codec (default: `h264` on Jetson, `auto` elsewhere). Same as [`collect-data`](/cli/collect-data). |
| `--root PATH` | Local dataset root (default: `$HF_LEROBOT_HOME`) |
| `--push_to_hub true` | Push the dataset to HuggingFace Hub when done. Log in first. See [Upload to the HuggingFace Hub](/operations/data-collection#upload-to-the-huggingface-hub). |
| `--robot_config.cameras DICT` | Camera slots and serial numbers, as in [`collect-data`](/cli/collect-data): `--robot_config.cameras "{overhead: {serial: 41234567}, left_arm: {serial: 41234568}, right_arm: {serial: 41234569}}"`. Assign the cameras the policy was trained on. At least one must record. |
| `--robot_config.axol_config.left_stiffness S` | Left arm stiffness in `[0, 1]` (default: 1). Match the value used to collect the policy's data. Use `right_stiffness` for the right arm. See [`AxolConfig.left_stiffness`](/api/robot). |
| `--teleop_config.vr_teleop_config.reset_torque_threshold FLOAT` | Contact limit (Nm) for every return to rest (default: 6.0). `0` turns it off. |
| `--teleop_config.vr_teleop_config.reset_gravity_comp_kd FLOAT` | Damping (Nm·s/rad) while the arms hang limp after a contact stop (default: 0.25). Same as [`gravity-comp`](/cli/gravity-comp) `--kd`. |
| `--rerun_ip IP` | IP of a Rerun viewer on your computer, for live visualization |
| `--rerun_port INT` | Rerun viewer port (default: 9876). Used only with `--rerun_ip`. |
| `--log_level {DEBUG,INFO,WARNING,ERROR}` | Default: `INFO` |
| `--config_path PATH` | Load a whole-config JSON/YAML file. Flags override it. |
| `--settings_path PATH` / `--no_settings` | Read another [shared settings file](/cli/configuration#the-shared-settings-file), or ignore it. By default `~/.almond/settings.json` applies, beneath `--config_path` and the flags. |

If a return to rest hits something, the arms stop and go limp in a gravity-compensation hold. Free them by hand, then press the VR **reset** button, or continue at the prompt, to return to rest from where they are. This works as in [`teleop`](/cli/teleop#contact-stops).

The video relay must start for this command. If it can't, install the GStreamer stack with [`gst.install`](/cli/gst-install) and [`gst.build-zed`](/cli/gst-build-zed).

```bash
axol collect-dagger --policy_path myorg/pick-place-policy --policy_type act \
    --task "Pick the red cube and place it in the bin" --repo_id myorg/pick-place-dagger \
    --robot_config.cameras "{overhead: {serial: 41234567}, left_arm: {serial: 41234568}, right_arm: {serial: 41234569}}"
axol collect-dagger --policy_path ./checkpoints/epoch_100 --policy_type smolvla \
    --task "Stack the blocks" --repo_id myorg/stack-dagger \
    --subtasks '["Grasp the top block", "Place it on the stack"]' \
    --robot_config.cameras "{overhead: {serial: 41234567}, left_arm: {serial: 41234568}, right_arm: {serial: 41234569}}"
```

## Local-policy intervention flow

The grip buttons move control between the policy and the operator during an episode.

| From | Grip action | To | Recording |
|---|---|---|---|
| **Policy** driving | Either grip alone | **Frozen**, robot holds pose | Paused |
| **Frozen** | Both grips | **Teleop**, operator drives | Resumes (rows tagged `intervention`) |
| **Teleop** | Either grip alone | **Policy** driving | Keeps running |

- When you take over, teleop engages at the robot's measured pose, so the arm doesn't jump.
- The grippers follow the controller triggers as soon as you take over. Set the triggers before you squeeze the grips. For example, hold a trigger down to keep a part gripped.
- When you hand back, the policy restarts its plan from the corrected pose.
- If the headset link drops while you drive, tracking disengages and control goes back to the policy.

Between episodes the grips work as plain teleop, and nothing is recorded. Squeeze both to engage and one to disengage, so you can reset the scene with the arms. The VR **reset** button sends the arms to rest. Inside an episode the reset button is disabled, and episodes end from the record button.

## Remote policies through the custom policy interface

`--policy_type custom` runs inference on a desktop through the custom policy interface. It requires `--hold_to_intervene true`:

- Hold either grip to drive that arm. The other arm holds its pose.
- Release both grips to hand control back to the policy.
- If the headset connection drops while you hold a grip, you keep control and the arm holds its position until you release.

The freeze and toggle controls above apply to local policies only.

For example, on the robot, with your endpoint address and camera serial:

```bash
axol collect-dagger --policy_type custom \
    --server_host 192.0.2.10 --server_port 8765 \
    --task "Pick the cube" --repo_id myorg/remote-policy-corrections \
    --hold_to_intervene true --record_joint_actions true \
    --home_on_start true --start_from_current_pose true \
    --robot_config.cameras "{overhead: {serial: 41234567}}"
```

The endpoint must accept the robot's state, action and camera layout. No checkpoint path is needed. `--task` labels the dataset and isn't sent to the endpoint, and the endpoint picks the instruction. Remote mode rejects `--subtasks`.

Set DAgger's own `server_host` and `hold_to_intervene`. The control panel shows these fields too. Run-policy's inference settings don't select the DAgger endpoint.

| Flag | Description |
|---|---|
| `--server_host HOST` / `--server_port INT` | Address and port of your policy endpoint (defaults: `127.0.0.1` / `8765`) |
| `--hold_to_intervene true` | Hold a grip to drive that arm. Required for remote policies. |
| `--shadow_inference BOOL` | Keep requesting predictions while you drive (default: `true`). They never move the motors. |
| `--handover_duration_s FLOAT` | Time to blend from your last command into the policy's plan when you hand back (default: `0.2667` s) |
| `--record_joint_actions true` | Record joint commands even when the policy sends Cartesian targets. Images and measured state keep their schema. |
| `--start_from_current_pose true` | Skip the startup home and the home after idle teleop. Episodes start where you left the arms. |
| `--home_on_start true` | With `--start_from_current_pose`, still home once at startup. |

When you hand back, the robot holds your last command until the desktop returns a fresh plan from the corrected pose. It then blends into that plan. Each switch between policy and operator stays in the same dataset episode, and the rows are labelled correctly at the switch.

The startup move must finish before the first VR Record prompt opens. Whenever the session homes on start (the default, or with `--home_on_start true`), it first checks that every arm joint is within 25° of zero, and the first home goes through zero. See [Starting needs the arms near zero](/operations/teleop). A session with `--start_from_current_pose` and without `--home_on_start` can start anywhere.

## Stopping a session

With a local policy, ending the session parks the arms as in `collect-data`. They go to rest, then to zero holding the grasp, then the motors turn off. Zero applies with `--teleop_config.vr_teleop_config.park_to_zero` (on by default; the control panel's **Park to zero on stop**). The moves are limited to 6 s and 10 s.

With a remote policy:

- Press `q` once to park through rest and zero, then turn off the motors. It needs no Enter and discards an episode in progress. It works at the idle VR Record prompt or during an episode.
- An idle `q` never starts the policy.
- During an episode, `s` + Enter saves and `r` + Enter discards.
- End-of-input, `Ctrl+C`, a fault, declining a contact retry or a failed park all stop without parking. The motors keep holding the arms' position.
- Arms already limp after a contact stop stay limp and don't park.

## DAgger annotation

Every dataset `collect-dagger` creates has LeRobot's per-frame `intervention` feature. It is `True` on rows you drove and `False` on the policy's rows, the same annotation LeRobot's DAgger rollout uses. Training can use it to weight or filter the corrections.

You can resume only a dataset that already has the `intervention` feature, which means one recorded by this command. Any other dataset is rejected.
