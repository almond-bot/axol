---
title: "migrate-dataset"
description: "Fix the end-effector poses in older Cartesian and Mantis datasets, in place."
---

`axol migrate-dataset` rewrites the Cartesian end-effector poses of a local
LeRobot dataset in place. It has two migrations. Pass one of these flags:

| Flag | Applies to |
|---|---|
| `--from-version <version>` | Cartesian datasets recorded by axol v0.1.31 or earlier (URDF root yaw). |
| `--mantis-tcp-rotation` | Mantis datasets recorded by axol 0.2.4 or earlier (Vive tracker-to-gripper rotation). |

Both migrations:

- Update every data parquet file and recompute the dataset statistics.
- Record what they did in `meta/axol.json`, so they can't run twice.
- Back up every file they replace under `meta/migrations/<migration-id>/`. If a migration fails, those files are restored. A later run finishes recovering an interrupted migration before it retries.

Videos, gripper values, timestamps and joint-space data are never changed.

## URDF frame

`--from-version`. Since v0.1.32 the robot's world frame has +x forward, +y left
and +z up, a 90° turn from the frame older Cartesian datasets use. The migration
applies that turn to the position and orientation of both end effectors in
`action` and `observation.state`.

```bash
# Inspect the dataset and report the scope without changing it
axol migrate-dataset --repo_id ilanri/checkers-demo-bimanual \
  --from-version v0.1.29 --dry-run

# Migrate it in place
axol migrate-dataset --repo_id ilanri/checkers-demo-bimanual \
  --from-version v0.1.29

# A dataset outside $HF_LEROBOT_HOME can be addressed directly
axol migrate-dataset --repo_id /data/checkers-demo-bimanual \
  --from-version v0.1.29
```

Only run this on Cartesian data recorded with axol v0.1.31 or earlier. A
joint-space dataset doesn't need it and is rejected.

Older datasets don't record which axol version made them. Check when and how
the dataset was recorded, then pass that version with `--from-version`. The
command rejects v0.1.32 and newer. Current Cartesian datasets record their pose
frame in `meta/axol.json`, and a dataset that has it is refused.

## Mantis tracker-gripper rotation

`--mantis-tcp-rotation`. Mantis collection converts every tracker pose to a
gripper pose before recording it. In axol 0.2.4 and earlier, that conversion
used the wrong rotation (`Rx(+90°)` instead of `Ry(180°)`) for the Vive mount.
Recorded orientations are pitched about 90° off, and Axol can't replay the
dataset: the arms barely move. This migration swaps in the correct rotation in
every recorded pose. Positions don't change.

```bash
axol migrate-dataset --repo_id CooperLiConduit/isolate-5 --mantis-tcp-rotation --dry-run
axol migrate-dataset --repo_id CooperLiConduit/isolate-5 --mantis-tcp-rotation
```

Add `--swap-sides` when the trackers were bound to the opposite rigs, so the
tracker `tracker.identify` labelled *left* was on the rig in the right hand.
In that case the dataset's `left_ee.*` columns hold the right hand's rig, and
every pose is turned 180°. `--swap-sides` swaps the left and right pose columns
and turns every pose 180° about the midpoint between the grippers at rest.
Gripper columns stay as recorded, because they follow the CAN channel, not the
tracker.

```bash
axol migrate-dataset --repo_id CooperLiConduit/isolate-5 --mantis-tcp-rotation --swap-sides
```

Signs of a swapped session:

- The hand the operator moved in the video is the *other* side in the dataset.
- After the rotation fix alone, both engage orientations are about 180° from the rest pose.

Axol 0.2.5 and later refuse to engage with swapped trackers, so only older
datasets need this.

Eligibility is checked before anything is written:

- `robot_type` must be `axol_mantis`; robot-recorded datasets never went
  through the tracker transform.
- `meta/axol.json` must exist and be in the v0.1.32+ pose frame (run
  `--from-version` first otherwise).
- `meta/axol.json` must **not** already have a `mantis_tcp_transform` record.
  Datasets recorded with 0.2.5 or later have one, as do migrated datasets, so
  they are refused. That includes datasets recorded with measured per-unit
  transforms (`"id": "measured"`). This migration only undoes the factory Vive
  rotation.

Don't run it on a pre-0.2.5 dataset recorded with an override in
`~/.almond/mantis/tcp_transform.json` or with a Quest source. Those never used
the wrong rotation. Don't run it on a dataset that mixes Mantis and robot
episodes either, since it changes every row.

After migration, `meta/axol.json` records `mantis_tcp_transform.id` as
`vive-flat-back-ry180-v0.2.5`, so the migration can't run twice. That
transform's offset differs from the current factory values (see
[Vive factory values](/cli/tracker#vive-factory-values)). `collect-data
--mantis` refuses to add episodes to a migrated dataset, so record new
episodes to a new `repo_id`.

## Options

| Option | Description |
|---|---|
| `--repo_id <id-or-path>` | Local repo id under `$HF_LEROBOT_HOME`, or a dataset directory path (required) |
| `--root <path>` | Alternate root containing the repo id |
| `--from-version <version>` | URDF-frame migration: axol version that recorded the dataset; must be older than v0.1.32 |
| `--mantis-tcp-rotation` | Mantis migration: replace the wrong Rx(+90°) Vive rotation with Ry(180°) |
| `--swap-sides` | With `--mantis-tcp-rotation`: the left/right trackers were bound to the opposite rigs |
| `--dry-run` | Check the dataset and report the files and rows that would change, without writing |
