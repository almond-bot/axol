---
title: "tune.factory"
description: "Calibrate friction and gravity for all 14 joints in one run, and share the result."
---

Calibrates friction ([`tune.friction`](/cli/tune-friction)) and gravity ([`tune.gravity`](/cli/tune-gravity)) for all 14 joints, both arms times seven, in one command. You can also run it from the diagnostics dashboard (`axol serve`). For a step-by-step walkthrough, see [Calibrating Axol](/guides/axol-calibration).

Each joint sweeps back and forth at several speeds. From one sweep the tool fits both the joint's friction and the center of mass of the link it moves.

- **Time:** about 6 minutes per joint, about 1.5 hours for both arms.
- **Order:** each arm runs from `wrist_3` to `shoulder_1`. Each joint's fit is saved before the next joint sweeps, so the shoulder fits use the corrected wrist and elbow values.
- **Poses:** the clearance and gravity-load poses are the same as in [`tune.friction`](/cli/tune-friction) and [`tune.gravity`](/cli/tune-gravity).

The default `slow` profile calibrates friction for slow, smooth motion. On `shoulder_1`, `shoulder_2` and `elbow`, a slow-profile calibration also switches the joint to stiffer [slow-motion gains](/operations/teleop-config). A joint without one keeps the standard gains.

## Where the results go

The results are saved to `~/.almond/calibration.json`, and this computer uses them right away. They are also uploaded under the serial number of Axol's hub, which stays with the arms when you swap the computer. The upload needs a write key in `.env`:

```bash
# .env on the computer you calibrate from
AXOL_SUPABASE_KEY=<service key with storage write access>
```

Without a key, the run calibrates this computer only and tells you so. Downloading needs no key.

The upload merges with what is already stored, joint by joint:

- A one-arm run keeps the other arm's values.
- A joint whose gravity fit is rejected keeps its earlier `com` and `mass`.
- An interrupted run keeps and uploads every joint that finished.

## Custom end-effectors

The gravity fit keeps each link's mass fixed and fits only its center of mass. The gripper and everything mounted on it count as the `wrist_3` link, including wrist cameras and their brackets. The stock mass, 0.75&nbsp;kg, includes the Camera Kit wrist camera and its mount. If you change the weight on the wrist, give the new `wrist_3` mass before you calibrate. Otherwise the extra weight is spread over the wrong links.

Set the mass in one of two places:

- In the control panel, under **General settings → Advanced**, in the `wrist_3` row of each arm's table. The run uses this mass for its fits and saves it with the calibration.
- On the command line, with `--mass wrist_3=<kg>`. This overrides the panel setting.

`--com` optionally sets a starting center of mass, in metres, in that arm's URDF link frame. A center of mass set in the panel overrides the fitted one when Axol runs, so the run warns you about it. Clear it in the panel, or use [`--keep-gravity`](#keeping-a-hand-tuned-gravity-model).

The mass and center of mass are written to `~/.almond/calibration.json` before the sweeps, so every fit uses them. They are uploaded with the calibration even if a fit fails. To go back to the standard gripper and Camera Kit wrist camera, pass the stock mass (`--mass wrist_3=0.75`) and calibrate again.

- A `--mass` without a side applies to every arm being calibrated.
- `--com` must name its side (`left.` or `right.`), because the arms are mirror images.
- An arm that isn't being calibrated, an unknown joint, or a mass of zero or less is an error, reported before anything moves.

```bash
axol tune.factory --mass wrist_3=0.78                                         # other wrist cameras on both arms
axol tune.factory --mass left.wrist_3=1.1 --com left.wrist_3=-0.03,0,-0.14    # one arm, seeded CoM
```

A few rejected gravity fits are normal, mostly on `elbow` and `wrist_1`. For a step-by-step walkthrough, and when a rejected fit needs attention, see [After you change the end-effector or add cameras](/guides/axol-calibration#after-you-change-the-end-effector-or-add-cameras).

### Keeping a hand-tuned gravity model

If you set link masses or centers of mass by hand in the control panel (**General settings → Advanced**), run with `--keep-gravity`. The run then fits friction against your settings and doesn't fit or save any mass or center of mass. `--mass` and `--com` still take priority over the settings. Without the flag, the run uses the masses from your settings, fits each center of mass, and warns you about any center of mass set in the settings.

```bash
axol tune.factory --keep-gravity
```

The saved calibration holds `friction`, `mass` (kg) and `com` for each joint:

```json
{
  "version": 1,
  "hub_serial": "004800345542501420373234",
  "left": {
    "wrist_3": {
      "friction": {"fc": 0.12, "k": 900.0, "fv": 0.05, "fo": -0.02},
      "mass": 1.1,
      "com": [-0.03, 0.0, -0.14]
    }
  }
}
```

| Flag | Description |
|---|---|
| `--arms {both,left,right}` | Which arms to calibrate (default: both) |
| `--left-channel IFACE` / `--right-channel IFACE` | CAN interface overrides (default: the Axol hub's interface names) |
| `--profile {slow,standard}` | `slow` (default) calibrates friction for slow motion. `standard` is a quicker 7–72°/s sweep without the slow-speed and load terms. |
| `--velocities DEG_S …` | Sweep speeds in deg/s (default: `1 2 3 5 8 15 30` for slow, `7.2 18 36 54 72` for standard) |
| `--stribeck-gain G` | Share of the extra low-speed friction to cancel, saved for every joint (default: 0.8 on `shoulder_1`, `shoulder_2` and `elbow`, 0 elsewhere) |
| `--raw-dir DIR` | Save each joint's raw sweep samples to `DIR/<side>-<joint>.csv`. Refit them later with `tune.friction --fit-csv`. |
| `--hub-serial SERIAL` | Robot identity for the upload (default: the attached hub's USB serial) |
| `--keep-gravity` | Keep the [hand-tuned gravity model](#keeping-a-hand-tuned-gravity-model) from the panel settings. Saves friction only. |
| `--mass [SIDE.]JOINT=KG` | Link mass for a [custom end-effector or wrist camera](#custom-end-effectors). Overrides the mass in the panel settings. Repeatable. |
| `--com SIDE.JOINT=X,Y,Z` | Starting link center of mass in metres, uploaded as given if the fit is rejected. Repeatable. |

<Note>
  The calibration tools (`tune.factory`, `tune.friction`, `tune.gravity`, `tune.breakaway`) move the arm under impedance control at fixed calibration gains, with gravity fed forward. They never use the motors' firmware position loops or the production gains. Every joint is held before anything moves.
</Note>

```bash
axol tune.factory                     # both arms, upload if credentials exist
axol tune.factory --arms left
axol tune.factory --raw-dir ~/factory-raw   # keep the raw sweeps too
axol tune.factory --profile standard  # the quicker sweep
```

## calibration.push

Uploads this computer's calibration file (`~/.almond/calibration.json`) under the hub serial. It merges joint by joint with what is already stored.

Use it after you calibrate joints one at a time with `tune.friction`, `tune.gravity` or `tune.pid`, so you don't have to run `tune.factory`. It needs the same write key. `--dry-run` shows what would be uploaded and needs no key.

```bash
axol calibration.push --dry-run
axol calibration.push
```

## calibration.pull

Downloads a robot's uploaded calibration into `~/.almond/factory_calibration.json`. This includes friction, link masses and centers of mass, so a custom gripper's weight comes along. It needs no key. [`can.setup`](/cli/can-setup) runs it at the end, so a new computer gets its robot's calibration during setup. Run it by hand to refresh:

```bash
axol calibration.pull                 # identity from the attached hub adapter
axol calibration.pull --hub-serial 004800345542501420373234
```

When a value is set in more than one place, this order applies, from lowest to highest priority:

1. The built-in defaults.
2. The downloaded calibration.
3. The calibration file on this computer, `~/.almond/calibration.json`.

Anything you save locally afterwards with `tune.friction --save`, `tune.pid --save` or `tune.gravity --save` overrides the downloaded values.
