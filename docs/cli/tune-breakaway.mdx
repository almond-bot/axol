---
title: "tune.breakaway"
description: "Measure a joint's static (breakaway) friction and compare it with its sliding friction."
---

Measures the torque at which a stationary joint starts to move, in both directions. This is the joint's static or **breakaway** friction. The tool compares it with the sliding friction `fc` that the friction model already holds.

A joint stick-slips when its breakaway friction is higher than its sliding friction. While it tracks a slow target, it sticks until the position error builds enough torque to break it free, then it overshoots and sticks again. [`tune.friction`](/cli/tune-friction) can't measure this gap, because its model has no separate static term. This command measures it directly.

## How it works

For each pose:

1. The arm homes and moves to the same safe clearance pose as [`tune.friction`](/cli/tune-friction).
2. The test joint moves to the pose, then drops its position spring (`kp = 0`). Only a small damping and the gravity feed-forward hold it.
3. The tool trims the gravity feed-forward until the joint stands still.
4. It ramps an extra torque up and back down. The first motion past `--move-deg` counts as the release, and the tool records the torque at that moment. The joint is then caught and returned to the pose.

Each attempt ramps a little higher and the run stops at the first release, so the joint never sees more torque than it took to move it.

## Reading the results

The report gives:

- **F_static**: the breakaway friction, averaged over both directions.
- **`F_static / fc`**: how much higher breakaway is than sliding friction.
- **Predicted stair**: `(F_static − fc) / kp`, in degrees. Compare it with the steps a slow [`tune.motion`](/cli/tune-motion) replay shows.
- **`stiction_gain` ceiling**: `F_static / fc − 1`. Compensation above this makes the joint hunt around its target at rest. Start at 60 to 80% of the ceiling.

| Flag | Description |
|---|---|
| `--l` / `--r` | Arm side (required) |
| `--channel IFACE` | SocketCAN interface override for setups without the Axol hub adapter |
| `--joint JOINT` | `shoulder_1`, `shoulder_2`, `shoulder_3`, `elbow`, `wrist_1`, `wrist_2`, `wrist_3` (required) |
| `--poses DEG [DEG ...]` | Joint-frame poses to probe, in degrees with 0 at rest (default: 0). Joints that could reach the base are kept 5° clear of it. |
| `--trials N` | Releases per direction (default: 3) |
| `--ramp-s S` | Seconds for one up-and-back torque ramp (default: 4) |
| `--max-torque M` | Largest ramp peak, as a multiple of the joint's `fc` (default: 3.0). At least 0.2 Nm on the wrists. |
| `--move-deg DEG` | Motion that counts as a release (default: 0.06) |
| `--kd KD` | Damping while the position spring is off, so a released joint creeps instead of running (default: 1.0) |
| `--csv PATH` | Write every ramp sample (`t, extra_nm, pos_deg, tau_nm`) to a CSV for plotting |

```bash
axol tune.breakaway --r --joint shoulder_1
axol tune.breakaway --r --joint shoulder_2 --trials 5 --csv ~/breakaway-s2.csv
axol tune.breakaway --r --joint shoulder_1 --poses -30 0 30   # load dependence
```

<Note>
  The test joint spends most of the run with no position spring. Only the trimmed gravity feed-forward and light damping hold it. Keep the space around the arm clear and the E-Stop within reach.
</Note>
