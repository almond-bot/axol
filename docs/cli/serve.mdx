title: "serve"

Runs the **Axol web control panel**, a local server that lets you drive the robot from a browser instead of a terminal. From the panel you can start, watch and stop teleoperation, gravity compensation, data collection, dataset replay and policy inference.

With the [one-command install](/installation), this command already runs as a system service (`axol.service`). It starts at boot and restarts automatically, and the control panel offers an update when a newer [release](https://github.com/almond-bot/axol/releases) exists. You run it by hand only on a development install:

```bash
axol serve                    # https://localhost:8001 (LAN-reachable)
axol serve --port 9000
axol serve --open             # also open a browser window on startup
axol serve --host 127.0.0.1   # localhost only
axol serve --no-tls           # plain HTTP instead of HTTPS
sudo "$(command -v axol)" serve              # hardware development (CAN setup, ZED daemon)
```

Run it with `sudo` so the panel can set up CAN and restart the ZED daemon.
Datasets go to `$HF_LEROBOT_HOME`, or to the panel's **Dataset root** setting.
When that folder is in a user's home, each recording is owned by that user
after every episode save, as with the installed service.

<Tip>
  For a walkthrough of the control panel, from connecting to Axol and assigning cameras to running each operation, see the [Web Control Panel guide](/guides/control-panel).
</Tip>

| Flag | Description |
|---|---|
| `--host HOST` | Interface to bind. Default `0.0.0.0` (reachable on the LAN); use `127.0.0.1` for localhost only. |
| `--port INT` | Port to listen on. Default `8001`. |
| `--open` | Open a browser window on startup. Off by default. |
| `--no-tls` | Serve plain HTTP instead of HTTPS. TLS is on by default. |

<Warning>
  `axol serve` is a trusted-LAN control service, not a multi-user authenticated API. Keep ports 8000/8001 behind the robot network or a host firewall; do not expose them directly to the internet.
</Warning>

## TLS

TLS is **on by default**, so HTTPS pages such as the hosted VR app at `axol.almond.bot` can reach this machine. On first run a self-signed certificate is created in `~/.almond/vr/certs/`. VR teleop uses the same certificate, so accepting it once covers both.

To connect from a browser on another machine, open the printed **LAN** URL once and accept the certificate warning. Pass `--no-tls` to disable TLS entirely (plain HTTP).

## Building the web UI

The server looks for the built web UI at `web/app/dist`, which exists only in a repo checkout. Without it, `axol serve` still runs and the **API is available**. Use the hosted UI at [axol.almond.bot](https://axol.almond.bot), which connects to the server directly. To serve the UI locally instead, build it once:

```bash
cd web
npm install
npm run build --workspace=packages/axol-vr-client
npm run build --workspace=app
```

For details, see [Build the web UI](/advanced/development-install#build-the-web-ui) in the development install guide.

## What it serves

| Path | Description |
|---|---|
| `/control` | The control panel UI (operations, connections, settings). |
| `/diagnostics` | The [diagnostics dashboard](/guides/diagnostics-dashboard): live motor data, health tiles and diagnostic scripts. |
| `/vr` | The [VR teleop interface](/guides/vr-interface). |
| `/` | Sends headset browsers to `/vr` and everything else to `/control`. |
| `/api/*` | JSON + WebSocket API used by the UI. |

<Note>
  Operations launched from the panel run inside the `serve` process, the same way as the [`teleop`](/cli/teleop), [`gravity-comp`](/cli/gravity-comp), [`waypoints`](/cli/waypoints), [`collect-data`](/cli/collect-data), [`replay-dataset`](/cli/replay-dataset) and [`run-policy`](/cli/run-policy) commands. Anything those commands need on the host is needed here too: CAN, the `lerobot`, `sim` and `tracker` extras, and ZED access.
</Note>
