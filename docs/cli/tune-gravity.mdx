---
title: "tune.gravity"
description: "Measure one link's center of mass from the motors to correct gravity compensation."
---

Measures one link's real center of mass from motor torques and corrects the gravity feed-forward with it. You can also run it from the diagnostics dashboard (`axol serve`). To calibrate every joint at once, use [`tune.factory`](/cli/tune-factory).

## When to use it

The gravity feed-forward starts from the CAD masses and centers of mass. Cables, the end-effector and build differences can make a real link a few percent off.

The position spring then has to carry the missing torque, so the joint sags under load by `unmodeled torque / kp`. Raising the gains won't fix the sag. Correcting the model fixes it at every angle.

## How it works

The joint sweeps back and forth at a constant speed, as in [`tune.friction`](/cli/tune-friction). Averaging the forward and backward torques cancels friction, which leaves gravity. The tool fits the difference from the current model as a shift in the link's center of mass.

- The link's mass stays at its CAD value. For a custom gripper much heavier than stock, set its mass first with [`tune.factory --mass`](/cli/tune-factory#custom-end-effectors).
- One joint's sweep can't see every direction of the center of mass equally well. Directions it can't see stay at their current value.
- A fitted shift of more than 60 mm is rejected as bad data.

## Sweep poses

Gravity can't turn a joint whose axis is vertical, so the tool poses other joints to load the test joint:

| Joint | Pose during the sweep |
|---|---|
| `shoulder_3` | `shoulder_1` raised so the upper arm is horizontal (+90° left, −90° right), elbow bent |
| `wrist_1` | Elbow bent, `wrist_2` at 85° |
| `wrist_2` | Elbow raised to clear the base, `wrist_1` at 90° |

The clearance rules from [`tune.friction`](/cli/tune-friction) also apply. `shoulder_2` sweeps only outboard of rest. `shoulder_3` and `wrist_1` sweep with `shoulder_2` held 10° outboard, and are limited to ±90° in their loaded poses. If a sweep would still carry no gravity load, the tool refuses to fit it.

## Order

Run from `wrist_3` to `shoulder_1`. A shoulder sweep moves every link past it, so errors in uncalibrated wrist and elbow links end up in the shoulder's fit. The tool prints a note when links further out are still uncalibrated.

Run [`tune.friction --save`](/cli/tune-friction) on the joint first. The tool refits the friction offset `Fo` against the corrected model and saves it with the center of mass.

| Flag | Description |
|---|---|
| `--l` / `--r` | Arm side (required) |
| `--channel IFACE` | SocketCAN interface override for setups without the Axol hub adapter |
| `--joint JOINT` | `shoulder_1`, `shoulder_2`, `shoulder_3`, `elbow`, `wrist_1`, `wrist_2`, `wrist_3` (required) |
| `--velocity DEG_S` | Sweep speed in deg/s (default: 18). Keep it at 25 or below, because the shoulder torque readings get noisy above that. |
| `--lo DEG` / `--hi DEG` | Override the sweep limits (degrees) |
| `--kp FLOAT` / `--kd FLOAT` | Gains during the sweep (default: the [calibration gains](/cli/tune-friction#calibration-gains)) |
| `--save` | Save the fitted center of mass, the refit `Fo` and the link mass to `~/.almond/calibration.json`. This computer then uses them everywhere. |
| `--save-run` | Save the sweep (measured and model torque per angle) for the dashboard charts |
| `--label NOTE` | Note stored with the saved run |

The report prints the center-of-mass shift in mm, how well the model fits before and after, and the worst sag at rest before and after, at the joint's configured `kp`.

```bash
axol tune.gravity --l --joint shoulder_1
axol tune.gravity --l --joint elbow --save
axol tune.gravity --r --joint wrist_1 --velocity 25 --save
```
