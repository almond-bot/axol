---
title: "tune.a4"
description: "Tune a joint's firmware position loop (0xA4) with a sine or constant-speed triangle."
---

Tunes the firmware position loop of one joint. This is the controller a joint runs when its `wire_mode` is `a4` (see the [config reference](/cli/configuration)).

The tool streams a sine or a constant-speed triangle to the joint with the firmware gains, speed cap and planner acceleration you choose. It scores how well the joint tracks and how smoothly it creeps, and saves the run for the diagnostics dashboard (**Tuning → Firmware loop**). You can also run it from the dashboard (`axol serve`).

[`tune.pid`](/cli/tune-pid) tunes the impedance (MIT) controller instead. Under 0xA4 the motor runs its own cascade of position, speed and current loops, so the settings here are:

- the firmware gains (`position_kp`, `position_ki`, `position_kd`, `speed_kp`, `speed_ki`, `current_kp`, `current_ki`)
- the speed cap (`--cap`)
- the position planner's acceleration (`--accel`)

## Planner acceleration

Use one of two values for `--accel`. Try both and compare.

| `--accel` | Behavior |
|---|---|
| `0` | The loop tracks the streamed target directly. |
| `60000` | The protocol maximum. The planner finishes each streamed step within one tick. |

Any value in between re-plans every streamed target, and the joint will not follow the wave.

## Reading the results

The triangle runs every pass at one slow speed, so it shows stick-slip along the whole pass and not only at the turnarounds. Compare runs on these scores:

- **Velocity ripple**: the spread of measured minus commanded velocity, divided by the commanded speed. Under 0.2 is smooth. Stick-slip reads near 0.8.
- **Stuck windows**: the share of 50 ms windows in which the joint stayed put while the target moved.
- **1–4 Hz error band**: tracking error in the band where stick-slip shows up.
- **Lag**: how far the joint trails the target.
- **>10 Hz buzz**: fast vibration.

## Safety

- Gains are written to RAM unless you pass `--persist`. When the run ends, the tool writes back the values the motor had before. Pass `--keep` to leave the run's values in place.
- A buzz guard stops the run on fast position motion or high current and restores the previous gains. Start each sweep from the stock values and change them in small steps. Large steps can make the joint vibrate.
- In this mode the joint holds position stiffly and pushes back against contact with full motor torque. Keep the workspace clear and the E-Stop within reach.

| Flag | Description |
|---|---|
| `--l` / `--r` | Arm side (required) |
| `--channel IFACE` | SocketCAN interface override |
| `--joint JOINT` | The joint to tune (required). `shoulder_1` to `wrist_1` run 0xA4, and the Damiao `wrist_2` and `wrist_3` run their position-velocity mode. |
| `--mode sine\|triangle` | Wave shape (default: `triangle`) |
| `--center DEG` | Center of the wave, joint-frame degrees (default: midpoint of the safe range) |
| `--amp DEG` | Half-travel, degrees (default: 10) |
| `--freq HZ` | Sine frequency (default: 0.3) |
| `--speed DPS` | Triangle pass speed, deg/s (default: 3) |
| `--duration S` | Seconds of wave (default: 12) |
| `--rate HZ` | Command rate (default: 400, the rate the realtime core streams `a4` joints at). Tune at the rate you will run. |
| `--cap DPS` | 0xA4 speed cap (default: 60) |
| `--cap-track K` | Set the speed cap to `K` times the commanded speed, between `--cap-floor` and `--cap` (default: 0, a fixed cap). Use `1.1` to `1.2` with `--accel 60000` to keep the joint moving smoothly. |
| `--cap-floor DPS` | Lowest cap `--cap-track` may set, so a stopped or reversing target can still correct (default: 1) |
| `--lead-ms MS` | Send each target this many milliseconds ahead along the wave, 0 to 50 (default: 0). The run is still scored against the true wave. |
| `--accel DPS/S` | Planner acceleration for the run, `0` or `60000` (see above). Written to ROM and restored afterwards unless `--keep` (default: leave the stored value). |
| `--position-kp`, `--position-ki`, `--position-kd`, `--speed-kp`, `--speed-ki`, `--current-kp`, `--current-ki` | Firmware gains for the run (default: leave as is). The tool prints the motor's current values at start. |
| `--pose JOINT=DEG` | Hold another joint at this joint-frame angle during the run, with the same rules as [`tune.pid`](/cli/tune-pid). Repeatable. |
| `--held-gain [SIDE.]JOINT.GAIN=VALUE` | Set a held joint's firmware gain for the run, in RAM. Repeatable. |
| `--dm-acc RAD_S2` | Damiao wrists only: the profiler's acceleration and deceleration for the run, restored afterwards unless `--keep` |
| `--persist` | Write gains to ROM instead of RAM |
| `--keep` | Leave the run's gains and planner acceleration in the motor |
| `--buzz-abort DEG` | Stop past this much >10 Hz position motion, degrees RMS over 0.1 s (default: 0.3; 0 turns it off) |
| `--iq-abort A` | Stop past this motor current (default: 30; 0 turns it off). Keep it well above the current the pose needs to hold the arm up. |
| `--tf-probe PCT` | Measure the motor's rated current instead of running the wave (see below) |
| `--no-imu` | Skip the wrist IMU. By default each run gets an `imu` shake score (see [`tune.motion`](/cli/tune-motion)). |
| `--save-run` | Save the run for the diagnostics dashboard |
| `--label TEXT`, `--group ID` | Note and sweep ID stored on the run |

```bash
axol tune.a4 --r --joint shoulder_1 --center -35 --amp 10 --mode triangle --speed 3 --accel 0 --save-run
axol tune.a4 --r --joint shoulder_1 --accel 0 --speed-kp 0.05 --speed-ki 0.0005 --save-run --label "skp 0.05"
axol tune.a4 --r --joint shoulder_1 --mode sine --freq 0.3 --accel 0 --position-kp 0.02 --save-run
```

## Tuning in the working pose

A firmware loop that is well damped with the arm hanging can oscillate with the arm extended. Use `--pose` to hold the other joints in the worst-case pose you will run. The tool samples every held joint during the wave and reports how far it drifted and how much it shook (`metrics.held` in the saved run).

## Damiao wrists

`wrist_2` and `wrist_3` run the same kind of cascade, with fewer gains: `position_kp`, `position_ki`, `speed_kp` and `speed_ki`. Their position is 16-bit, and the current columns show torque in Nm. Their profiler always shapes the target. The stock profiler setting, 2 rad/s² (about 115°/s²), is too slow to follow a streamed target, so set a higher one with `--dm-acc`.

## Rated current probe

`--tf-probe PCT` holds the joint at `--center` on 0x73 (position control with torque feed-forward). It then steps the feed-forward between 0, +PCT, 0 and −PCT percent of rated current, 0.25 s each, for 8 s. From the current jump at each step it prints the motor's rated current. Enter that value as `firmware.tf_rated_current_a` in the config.

`5` is a gentle setting, about 1 Nm on a shoulder. The probe needs MyActuator V4.4 firmware. Run it with `--accel 0`.

<Note>
  You don't have to persist a winning set from here. The robot config carries per-joint `firmware.*` gains (see the [config reference](/cli/configuration)), and the robot writes any that differ to the motor when it enables the joint. Every joint's `firmware` block is empty by default, because the arms run impedance control. To try gains in an `a4` run, use `tune.motion --gain SIDE.JOINT.firmware.FIELD=VALUE` or set them in your config.
</Note>

<Warning>
  A joint left with planner acceleration 0 moves to any stored position target at the speed cap as soon as it wakes. `tune.a4` restores the stored acceleration unless you pass `--keep`. If you keep it, don't send that joint any other position command until you have set it back.
</Warning>
