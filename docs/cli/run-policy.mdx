---
title: "run-policy"
description: "Run a trained policy autonomously on the robot with async inference."
---

Runs a trained policy on the robot, using the ZED cameras attached to it.

- LeRobot policy types use LeRobot's async inference. A policy server starts on the robot, unless `--server_host` points to a remote [`inference-server`](/cli/inference-server).
- `--policy_type custom` connects to your own endpoint through the [custom policy interface](/api/policy-plan). See [Custom policy interface](#custom-policy-interface).

During a rollout, type a key on the terminal:

- `s` saves the rollout and ends the episode.
- `r` discards it. The arms go limp so you can move them by hand, since a failed rollout often leaves them in a bad spot. Clear them, then press **Enter** to return to rest and record again.
- `q` discards it and quits.

`--episode_time_s` limits each episode. When time runs out with no key pressed, you get the same prompt: **Enter** saves, `r` discards, `q` quits.

<Warning>
  Load only policy checkpoints and existing rollout datasets that you created
  or obtained from a trusted source. Loading them is not sandboxed.
</Warning>

<Tip>
  For the end-to-end workflow, including running inference on a GPU machine, see the [Run Policy guide](/operations/run-policy).
</Tip>

This command is configured through draccus. The robot settings (cameras, per-joint gains) live in the nested `robot_config`. Set them with dotted flags or a whole-config file. See [Command configuration](/cli/configuration) for the syntax and [Run Policy Config Parameters](/operations/run-policy-config) for every field with its default.

| Flag | Description |

| `--policy_type {act,smolvla,diffusion,tdmpc,vqbet,pi0,pi05,groot,custom}` | Policy type (required). LeRobot types must match `--policy_path`. `custom` selects the [custom policy interface](/api/policy-plan); see [Run Your Own Policy](/operations/custom-policy). |
| `--policy_path PATH_OR_REPO` | Local checkpoint path or HuggingFace repo ID. Required for LeRobot types, unused for `custom`. |
| `--task TEXT` | Natural language task description (required). With `custom` it labels the dataset and isn't sent to the endpoint. |
| `--episode_time_s INT` | Longest episode in seconds (default: 120). Episodes normally end on a key press. |
| `--fps INT` | Control loop rate (default: 30). Must match the rate the policy was trained on. |
| `--repo_id <user>/<dataset>` | Dataset repo ID to save rollouts to (optional) |
| `--root PATH` | Local dataset root (default: `$HF_LEROBOT_HOME`) |
| `--push_to_hub true` | Push the rollout dataset to HuggingFace Hub when done. Log in first. See [Upload to the HuggingFace Hub](/operations/data-collection#upload-to-the-huggingface-hub). |
| `--vcodec STR` | Video codec for saved rollouts (default: `h264` on Jetson, `auto` elsewhere). Used only with `--repo_id`. |
| `--device STR` | PyTorch device for LeRobot inference (default: `cuda`; unused with `custom`). The hosted Jetson install has CPU-only PyTorch, so use `cpu` or remote inference. |
| `--server_host HOST` | Address of a remote [`inference-server`](/cli/inference-server). Default `null` starts a policy server on the robot. With `custom`, the address of your endpoint (default `127.0.0.1`); a `ws://` or `wss://` URL also works. |
| `--server_port INT` | Policy server or endpoint port (default: 8765) |
| `--actions_per_chunk INT` | Most actions per inference call (default: 50) |
| `--plan_config.request_interval INT` | Custom policies: request a new plan after this many actions (default: 5) |
| `--plan_config.max_adoption_offset_steps INT` | Custom policies: oldest a reply can be, in control steps since its request, and still be used (default: 6). Must be less than `--actions_per_chunk`. |
| `--plan_config.late_policy {abort,blocking_refresh}` | Custom policies: when a reply is too late or the plan runs out, stop (`abort`) or hold and request a fresh plan (`blocking_refresh`, the default) |
| `--chunk_size_threshold FLOAT` | LeRobot policies only: request a new chunk when the queue drops to this fraction of a chunk (default: 0.9) |
| `--aggregate_fn {temporal_ensemble,weighted_average,latest_only,average,conservative}` | LeRobot policies only: how overlapping action chunks are combined (default: `temporal_ensemble`, from the ACT paper) |
| `--temporal_ensemble_coeff K` | LeRobot policies only: decay for `temporal_ensemble` (default: 0.01). Higher is smoother, `0` weights all chunks equally, and negative is more reactive. |
| `--ensemble_blend_s FLOAT` | LeRobot policies only: fade each chunk out over its last this-many seconds (default: 0.2). `0` turns it off. |
| `--align_fade_s FLOAT` | LeRobot policies only: fade in a new chunk's offset from the current motion over this many seconds (default: 1.0). `0` turns it off. |
| `--exec_max_vel FLOAT` | Per-joint velocity limit (rad/s) on every command sent to the arms (default: teleop's limit) |
| `--exec_max_accel FLOAT` | Per-joint acceleration limit (rad/s²) on every command (default: teleop's limit). Set either limit to `0` to turn the filter off. |
| `--max_first_action_offset_rad FLOAT` | Largest allowed gap between the first action and the arm's current pose (default: 0.15 rad). `0` turns the check off. See [First-action check](#first-action-check). |
| `--reset_torque_threshold FLOAT` | Contact limit (Nm) for the return to rest between episodes (default: 6.0). `0` turns it off. |
| `--reset_gravity_comp_kd FLOAT` | Damping (Nm·s/rad) while the arms hang limp after a contact stop (default: 0.25). Same as [`gravity-comp`](/cli/gravity-comp) `--kd`. |
| `--policy_torque_threshold FLOAT` | Contact limit (Nm) while the policy drives (default: `0`, off). The control panel suggests `16.0`. |
| `--park_to_zero BOOL` | On **Stop**, `Ctrl+C` or `q`, move the arms from rest on to the all-zero pose before releasing the motors (default: `true`). Control panel: **Park to zero on stop**. |
| `--robot_config.cameras DICT` | Camera slots (`overhead`, `left_arm`, `right_arm`) and each ZED camera's serial number, as one inline value: `--robot_config.cameras "{overhead: {serial: 41234567}, left_arm: {serial: 41234568}, right_arm: {serial: 41234569}}"`. | `--robot_config.axol_config.<side>.gripper.torque_limit FLOAT` | Max torque (Nm) for a gripper (default: 0.5). `<side>` is `left` or `right`. |
| `--robot_config.axol_config.left_stiffness S` | Left arm stiffness in `[0, 1]` (default: 1, the tuned production gains). Match the value used to collect the data. Use `right_stiffness` for the right arm. See [`AxolConfig.left_stiffness`](/api/robot). |
| `--rerun_ip IP` | IP of a Rerun viewer on your computer, for live visualization |
| `--rerun_port INT` | Rerun viewer port (default: 9876). Used only with `--rerun_ip`. |
| `--log_level {DEBUG,INFO,WARNING,ERROR}` | Default: `INFO` |

| `--settings_path PATH` / `--no_settings` | Read another [shared settings file](/cli/configuration#the-shared-settings-file), or ignore it. By default `~/.almond/settings.json` applies, beneath `--config_path` and the flags. |

## Cameras and observations

The GStreamer and ZED SDK backends produce visibly different images. Run the policy through the backend its dataset was recorded with, or it sees images it was never trained on. The startup log names the backend in use: `Cameras: gst pipeline` or `Cameras: ZED SDK`. The GStreamer backend is used only when the plugin installed by [`gst.build-zed`](/cli/gst-build-zed) is verified.

Each observation pairs the camera images with the arm state from the moment the images were exposed. If a camera goes stale, or the images and arm state are too far apart in time, the rollout stops rather than feed the policy a mismatched observation.

## Safety checks

### First-action check

For joint-space policies, run-policy compares the first action of each episode with the arm's measured pose. If any arm joint is more than `--max_first_action_offset_rad` away:

- Nothing is sent to the arms and the episode is discarded.
- The log and the control panel name the joint and the offset.
- Continue to start the next attempt.

Demonstrations start from rest, so a large first offset usually means the policy sees inputs it wasn't trained on, such as a different scene or camera backend. Grippers and Cartesian actions aren't checked. Any accepted first action is still ramped in, not sent as one step.

### Contact stops

If the return to rest between episodes hits something, the arms stop and go limp in a gravity-compensation hold. Free them by hand, then continue (**Enter** or the panel's **Return to rest**) to return to rest from where they are.

With `--policy_torque_threshold` set, the same check runs while the policy drives. A stop ends the episode without saving and drops the arms limp. Clear them, then continue to return to rest and start the next attempt.

## Saving rollouts

With `--repo_id`, each saved episode is added to a LeRobot-format dataset. Resuming and repair work as in [`collect-data`](/cli/collect-data#saving-and-resuming), and each episode is on disk as soon as it saves. Between episodes the arms return to rest along a collision-aware path.

## Starting and stopping

**Starting needs the arms near zero.** Run-policy refuses to start while any arm joint is more than 25° from zero, the arms' natural resting pose. It names each joint that is out. Move them back by hand, for example under [`axol gravity-comp`](/cli/gravity-comp), and start again. The first move then goes through zero on its way to the rest pose. See [Starting needs the arms near zero](/operations/teleop).

**Stopping parks the arms.** When you end a run with `Ctrl+C`, `q` or **Stop** in the control panel:

1. The arms return to the rest pose.
2. With **Park to zero on stop** (`--park_to_zero`, on by default), they continue to zero, holding their grasp.
3. The motors turn off.

The return to rest has 6 s and the move to zero has 10 s. If a move runs out of time or hits something, the motors turn off where the arms are. A second `Ctrl+C` doesn't interrupt the park.

The park is skipped when the run never moved the arms, when a contact hold has left them limp, when the IK process never started, or when the CAN bus has stopped reporting positions.

## Custom policy interface

`--policy_type custom` connects to your endpoint through the custom policy interface. The robot sends compressed observations and keeps running the current plan while the endpoint computes the next one. When a new plan arrives, the robot skips the rows whose time has already passed. The endpoint must use protocol `version: 2`. Endpoints on the original protocol are refused.

```bash
axol run-policy --policy_type custom --server_host 192.0.2.10 \
    --task "Pick the red cube" --actions_per_chunk 30 \
    --robot_config.cameras "{overhead: {serial: 41234567}}"
```

Write the endpoint with the [`almond_axol.policy`](/api/policy) SDK (`Policy` and `serve()`), and test it without the robot using [`policy.check`](/cli/policy-check). See the [custom policy interface documentation](/api/policy-plan) for setup, timing and recovery.
