---
title: "zed.driver"
description: "Update a ZED Box or ZED Link camera driver to the version the ZED SDK needs."
---

Updates the GMSL camera driver on a ZED Box, or the ZED Link card driver on a Jetson AGX Orin, to the Stereolabs release that matches the ZED SDK.

| Carrier | Package | Pinned release |
|---------|---------|----------------|
| ZED Box Duo | `stereolabs-zedbox-duo` | 1.4.3 (L4T 36.4) |
| ZED Box Mini | `stereolabs-zedbox-mini` | 1.4.3 (L4T 36.4) |
| ZED Link Duo (Jetson AGX Orin) | `stereolabs-zedlink-duo` | 1.4.4 (L4T 39.2) |

```bash
axol zed.driver
```

The ZED SDK needs a matching driver. A unit may ship from the factory with an older driver, and with a newer SDK that driver restarts the camera service during capture, which stops the camera stream mid-session. `zed.driver` removes the factory package and installs the pinned one, following Stereolabs' procedure.

[`provision`](/cli/provision) runs this for you, so you rarely need to run it yourself.

## When it does nothing

- No `stereolabs-zed*` package is installed.
- The installed driver is already at the pinned version or newer.
- The Jetson's L4T release doesn't match the one the pinned driver was built for.

If a Stereolabs driver package is installed that isn't in the table, `zed.driver` logs a warning and leaves it alone.

The downloaded package must match a pinned SHA-256 checksum. If Stereolabs changes the file, `zed.driver` rejects it.

<Warning>
  The new driver loads only at boot, so you must **reboot** after the update. Run by itself, `zed.driver` only prints a notice. [`axol provision`](/cli/provision#reboots), the installer and the `axol serve` updater reboot for you at a safe time. The updater waits until no operation is running.
</Warning>
