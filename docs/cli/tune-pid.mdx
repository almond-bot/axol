---
title: "tune.pid"
description: "Sweep and rank Kp/Kd gains for a single joint via sinusoidal or step-response tracking."
---

Tests one or more `Kp`/`Kd` candidates for a single joint at ~100 Hz — pass several values to either flag to sweep the whole grid in one session — measures tracking error (RMS, max, overshoot, settling), ranks the candidates, and can save the winner to this robot's calibration file. Also available from the diagnostics dashboard (`axol serve`).

The feedforward path defaults to exactly what the production control loop applies — gravity + friction + inertia (`j_eff`) + host-side damping (`kd_host`) — so gains found here transfer 1:1 to teleop. Use `--ff` to tune against a reduced feedforward instead (e.g. `--ff none` for bare PD, or `--ff friction` to see how the joint behaves without gravity compensation), and `--host-kd` to override the host-side damping (the shoulders need it — their motor firmware's velocity estimate is too filtered to damp the ~2 Hz closed-loop resonance, so firmware `kd` alone leaves them ringing).

During every probe the other joints are held at rest by the motor firmware's own position servo (the stiffest hold available), and the tool round-robins one position read per cycle across them to prove they actually stayed put: each candidate's report ends with a `Holder peak` line listing how far every holder moved from its pre-step baseline. Past ~0.5° the structure was flexing under the reaction torque, and part of the measured ring belongs to a compliant neighbour rather than the joint under test.

| Flag | Description |
|---|---|
| `--l` / `--r` | Arm side (required) |
| `--channel IFACE` | SocketCAN interface override for setups without the Axol hub adapter |
| `--joint JOINT` | `shoulder_1`, `shoulder_2`, `shoulder_3`, `elbow`, `wrist_1`, `wrist_2`, `wrist_3` (required) |
| `--kp KP [KP ...]` | Proportional gain candidate(s) (default: the joint's configured kp) |
| `--kd KD [KD ...]` | Derivative gain candidate(s) (default: the joint's configured kd) |
| `--ff {full,gravity,friction,none}` | Feedforward during the test (default: `full` — matches production) |
| `--host-kd KD` | Host-side damping (Nm·s/rad) via `t_ff` — matches the production `kd_host` term (default: the joint's configured `kd_host`) |
| `--host-kd-hz HZ` | Band-pass centre (Hz) confining the host damping to the joint's resonance band — matches the production `kd_host_hz`; aim it at the ring frequency the step test reports (default: the joint's configured value, else the shared 3.2 Hz) |
| `--host-kd-q Q` | Quality factor of that band-pass (bandwidth = centre/q) — matches the production `kd_host_q` (default: the joint's configured value, else the shared 0.8). At 0.8 the band is an octave wide either side and, with a low centre, reaches into the <1.5 Hz intentional-motion band where the damping drags the final approach (the step never settles). With the centre on a measured ring, q 2–3 damps the ring only |
| `--mode {sine,step}` | `sine` = sinusoidal tracking (default); `step` = step response |
| `--amp DEG` | Motion amplitude in degrees (default: 10°, clamped to joint headroom) |
| `--freq FLOAT` | [sine] Frequency in Hz (default: 1.0) |
| `--duration FLOAT` | [sine] Duration in seconds (default: 5.0) |
| `--hold FLOAT` | [step] Hold time per phase in seconds (default: 2.0) — also the length of the unscored settle at the center before the step, so arrival/gain-change ringing dies out before anything is measured |
| `--rate FLOAT` | Command rate in Hz (default: 100.0; production teleop runs 240). The loop runs open-throttle when CAN round trips exceed the cycle budget, so the report prints the rate actually achieved and warns when it saturates below the request. Gains tuned at a lower rate see more host-damping transport delay than teleop will |
| `--save` | Save the best candidate's Kp/Kd to `~/.almond/calibration.json` |
| `--save-run` | Persist each candidate's full time series and metrics as a tuning-run artifact (`~/.almond/diagnostics/tuning/`) for charting and A/B comparison in the diagnostics UI |
| `--dump-csv [PATH]` | Write per-sample `(kp, kd, t, target, actual, error)` rows to a CSV for offline plotting. Pass without a value to auto-name as `logs/pid_<side>_<joint>_<timestamp>.csv` |

```bash
axol tune.pid --l --joint elbow                              # config gains, production FF
axol tune.pid --l --joint elbow --kp 20 30 45 --kd 0.5 1.0   # 6-way sweep, ranked
axol tune.pid --r --joint shoulder_1 --mode step --ff none   # bare-PD step response
axol tune.pid --l --joint wrist_1 --kp 12 --kd 0.4 --save    # persist to calibration
```

## Per-robot calibration

`--save` writes the winning gains to `~/.almond/calibration.json`, which `AxolConfig` loads on construction — every operation on the machine (teleop, data collection, policies) then uses the saved values instead of the shared defaults, while explicit overrides (`--axol.left.elbow.kp 60`, the panel's Advanced settings) still win over both. Saved `kp`/`kd` are the compliant (`s=0`) endpoint of the stiffness blend, like the defaults they replace. Friction values saved by [`tune.friction --save`](/cli/tune-friction) live in the same file.
