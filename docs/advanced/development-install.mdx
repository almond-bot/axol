This page is for **working on the Axol software itself**: installing from a source checkout, choosing optional extras and building the web UI. To run Axol on the robot, use the [one-command install](/installation) instead.

## Install from a clone

In your checkout, install the package with [`uv`](https://docs.astral.sh/uv/). Every dependency comes from PyPI:

```bash
uv sync
```

Then activate the virtual environment so the `axol` CLI is on your path:

```bash
source .venv/bin/activate
```

<Tip>
  Activate the environment in every new shell. Or start each command with `uv run` (for example, `uv run axol can.setup`) and skip activation.
</Tip>

## Optional extras

Add optional extras as you need them. The install script includes `lerobot`, `sim` and `tracker`.

| Extra | Contents | When to use |
|---|---|---|
| `lerobot` | LeRobot (from PyPI, pinned to 0.6.1) | `collect-data`, `run-policy` |
| `sim` | viser | `teleop --sim` |

```bash
uv sync --extra lerobot --extra sim --extra tracker   # same extras as the install script
```

<Warning>
  On a Jetson, the PyTorch package from PyPI has no GPU support. `uv sync` also replaces any GPU build of PyTorch you installed yourself. To run policies on the Jetson's GPU, install a PyTorch and Torchvision build for your JetPack version after each `uv sync`. Remote inference and `--device cpu` work without it.
</Warning>

<Note>
  Streaming the ZED cameras to the headset (`teleop --cameras`, `collect-data`) is not an extra. It needs system packages that [`axol provision`](/cli/provision) installs. See [Headset-video stack](#headset-video-stack) below.
</Note>

## ZED Python bindings

The ZED Python bindings (`pyzed`) are not on PyPI. Install the ZED SDK first, then run:

```bash
axol zed.install
```

See [`zed.install`](/cli/zed-install) for details.

## Headset-video stack

Streaming the ZED cameras to the headset needs GStreamer, **PyGObject** and Axol's patched ZED GStreamer plugins. None of these come from PyPI. [`axol provision`](/cli/provision) installs them all, and it is safe to run again. The install script and the updater run the same command:

```bash
axol provision
```

Its main steps are listed below, in the order they run. Each optional step is skipped on hardware it doesn't apply to. You can also run most of them on their own.

| Step | What it does |
|---|---|
| Quest over USB | Installs `adb` for the [Quest-over-USB](/guides/quest-over-usb) link. |
| [`tracker.install`](/cli/tracker#axol-trackerinstall) | Installs Lighthouse tracking for [Mantis](/mantis/tracking). |
| [`zed.driver`](/cli/zed-driver) | Upgrades the GMSL camera driver on a ZED Box Duo or Mini, or a ZED Link Duo on an AGX Orin. |
| `gyro.install` | Gives access to the board's motion sensor, which [Jelly](/guides/vr-interface#jelly) uses to hold its heading. |
| [`zed.install`](/cli/zed-install) | Installs the ZED Python bindings. |
| [`gst.install`](/cli/gst-install) | Installs GStreamer and PyGObject. |
| [`gst.build-zed`](/cli/gst-build-zed) | Builds the patched ZED GStreamer plugins. |
| `rt.install` | Installs the realtime core that controls the arms. This step is required. |
| [`jetson.setup`](/cli/jetson-setup) | On a Jetson, tunes power, clocks and scheduling for real-time control. |

The Jetson tuning resets when the computer restarts. The install script's service applies it again at every boot with `axol provision --boot`. On a development checkout without that service, run `axol provision --boot` yourself after each restart.

## First-run hardware setup

Before you run any motor or robot command, set up the CAN bus once:

```bash
axol can.setup
```

The command asks for `sudo` when it needs it. It also installs a service that brings the CAN interfaces back up when you unplug and replug an adapter. See [`can.setup`](/cli/can-setup) for details, and [`can.enable`](/cli/can-enable) to bring the interfaces up again by hand.

## Build the web UI

`axol serve` serves the web UI from `web/app/dist`. To serve the control panel and VR interface from your own computer, build it once:

```bash
cd web
npm install
npm run build --workspace=packages/axol-vr-client   # client package first
npm run build --workspace=app                        # → web/app/dist
```

Then start the server and open the printed URL:

```bash
axol serve
```

You can skip the build. Without it, `axol serve` still runs, and the hosted UI at [axol.almond.bot](https://axol.almond.bot) connects to it. See [`serve`](/cli/serve) and the [Web Control Panel guide](/guides/control-panel).
