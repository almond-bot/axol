---
title: "Quest over USB"
description: "Send Quest controller poses to the robot over a USB cable instead of Wi-Fi to cut teleop lag."
---

By default the Quest sends controller poses to the robot over Wi-Fi. On some networks, Wi-Fi power saving holds poses back and releases them in bursts, with gaps of about 150 ms. The arms then move in jerky, delayed steps. **Quest over USB** sends the poses over a USB cable instead.

<Note>
  USB carries controller poses only. Camera video still uses the network, so connect to the robot's address as usual.
</Note>

With USB on, the headset sends each pose over both the cable and Wi-Fi, and the robot uses whichever copy arrives first. If the cable drops, Wi-Fi takes over with no reconnect. When the cable comes back, USB takes over again.

## One-time setup

<Steps>
  <Step title="Enable Developer Mode on the Quest">
    1. Open the **Meta Quest** mobile app on your phone, with your headset connected.
    2. Go to **Menu → Devices**, select your headset, then **Headset Settings → Developer Mode**, and turn it on. The app may ask you to create a free Meta organization first.
    3. Restart the headset.

    This is the same Developer Mode used for [remote teleop](/guides/remote-teleop#sideload-tailscale-on-the-quest).
  </Step>

  <Step title="Confirm adb is installed on the robot machine">
    The [one-command install](/installation) runs [`axol provision`](/cli/provision), which installs `adb` and the Quest USB permissions. On a development install, run `axol provision` once.
  </Step>
</Steps>

## Connect and drive

<Steps>
  <Step title="Plug the headset into the robot machine">
    Use a data-capable USB-C cable from the headset to the machine running [`axol serve`](/cli/serve) (the one wired to the robot).
  </Step>

  <Step title="Authorize and connect from the control panel">
    In the [control panel](/guides/control-panel#quest-usb), open the **Quest** tab under **General settings** to see the headset's state. The first time, put on the headset and accept the **Allow USB debugging?** prompt. Tick **Always allow from this computer**.

    The link then connects on its own and the status turns green: **Controller over USB**. If it doesn't, press **Connect**.
  </Step>

  <Step title="Confirm the tunnel on localhost">
    In the headset browser, open `https://localhost:8001` and accept the certificate warning. This is the control panel, reached over the cable. If it loads, the cable link works. You can also use the control panel from the headset this way.

    <Note>
      The browser approves each port separately. Accepting the warning on port 8001 doesn't cover port 8000, which you approve in a later step.
    </Note>
  </Step>

  <Step title="Enable USB in the VR app">
    Open the VR app at [axol.almond.bot](https://axol.almond.bot), enter the robot's address as usual, and tick **Quest over USB**. The USB status and the **Authorize USB certificate** button appear right away, before you connect.
  </Step>

  <Step title="Authorize the USB certificate">
    The USB link uses port 8000, which needs its own approval. Until you approve it, the app uses Wi-Fi and shows *Quest over USB: not connected, using Wi-Fi*.

    1. Start a teleop or data collection operation from the control panel. Port 8000 is open only while one is running.
    2. Tap **Authorize USB certificate** and accept the warning. You can also open `https://localhost:8000` in the headset browser.

    The status changes to *Quest over USB: connected*.
  </Step>

  <Step title="Enter VR">
    Press **Enter VR** and teleoperate as usual. You don't have to wait for the USB link. Wi-Fi drives the arms until the cable link is up, and then the robot switches to it.
  </Step>
</Steps>

## Troubleshooting

| The **Quest** tab shows | Fix |
|---|---|
| **Authorize on headset** | Put on the headset and accept the **Allow USB debugging?** prompt. |
| **No headset** | Plug the cable in again, and check that Developer Mode is on. |
| **adb not installed** | Run `axol provision` on the robot's computer, then reconnect the headset. |
| **Headset ready**, but the link doesn't connect | Press **Connect**. If it still fails, try another cable. A faulty cable is the most common cause. |
