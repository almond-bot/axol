---
title: "Remote Teleop"
description: "Drive Axol over the internet by putting the Quest and the Host Computer on one Tailscale network."
---

[Teleoperation](/operations/teleop) normally runs over your local network, with the headset and the Host Computer on the same Wi-Fi. To drive Axol from anywhere over the internet, put the Meta Quest and the Host Computer on the same [Tailscale](https://tailscale.com) network (a "tailnet"). The headset then reaches the robot by its Tailscale address as if it were on the same network, and the traffic is encrypted.

Tailscale isn't in the Meta Quest Store, so you have to sideload it. This guide covers that, then the connection.

<Note>
  Remote teleop is sensitive to latency. Tailscale usually connects the two devices directly. When it can't, it sends traffic through a relay, which adds latency. You get the best results on connections with a low round-trip time.
</Note>

## Sideload Tailscale on the Quest

The Quest runs Horizon OS, which is based on Android, so you can install Tailscale's Android app from its APK file.

<Steps>
  <Step title="Enable Developer Mode on the Quest">
    1. Open the **Meta Quest** app on your phone, with your headset connected.
    2. Go to **Menu → Devices**, select your headset, then **Headset Settings → Developer Mode**, and turn it on. You may need to create a free Meta "organization" first, which takes a minute.
    3. Restart the headset.
  </Step>

  <Step title="Download the Tailscale APK">
    Download the Android APK from Tailscale's package server at [pkgs.tailscale.com/stable/#android](https://pkgs.tailscale.com/stable/#android) onto your computer.

    <Warning>
      Download the APK only from Tailscale's site, not from third-party APK mirrors.
    </Warning>
  </Step>

  <Step title="Sideload it with SideQuest">
    The easiest tool is [SideQuest](https://sidequestvr.com):

    1. Install SideQuest on your computer from [sidequestvr.com](https://sidequestvr.com).
    2. Connect the Quest to your computer with a USB-C cable.
    3. Put the headset on and accept the **Allow USB debugging?** prompt. Check **Always allow from this computer**.
    4. In SideQuest, press **Install APK from folder** and select the Tailscale APK.

    If you already use ADB, you can skip SideQuest and run `adb install tailscale.apk`.
  </Step>

  <Step title="Launch and log in">
    Tailscale doesn't appear in your normal app grid. Find it under **Unknown Sources** in your Quest app library (the folder icon with a "?"). Open it, sign in to your tailnet, and approve the VPN connection prompt.

    <Tip>
      The Android app isn't built for VR, so signing in inside the headset can be awkward. Signing in with an auth key or QR code is often easier than typing a password.
    </Tip>
  </Step>
</Steps>

<Note>
  A sideloaded Tailscale doesn't update itself. Sideload a newer APK from time to time.
</Note>

## Connect the Host Computer to the same tailnet

On the Host Computer, install Tailscale and start it (see [Tailscale's Linux install docs](https://tailscale.com/download/linux)):

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

Sign in to the **same tailnet** as the headset. Note the computer's Tailscale address: its `100.x.y.z` IP or its MagicDNS name. Run `tailscale ip -4`, or check the [Tailscale admin console](https://login.tailscale.com/admin/machines).

## Drive the robot

With both devices on the tailnet, use [teleoperation](/operations/teleop) as usual, with the Tailscale address instead of the local one:

<Steps>
  <Step title="Start teleop on the Host Computer">
    Start it from the [control panel](/guides/control-panel) or with `axol teleop`, as for local teleop.
  </Step>

  <Step title="Check that Tailscale is connected in the headset">
    Open the Tailscale app on the Quest and check that the VPN is on.
  </Step>

  <Step title="Enter the Tailscale address in the VR app">
    Open the VR app at [axol.almond.bot](https://axol.almond.bot) on the headset. In the **Connect** field, enter the robot computer's **Tailscale IP or MagicDNS name** instead of its local IP. Press **Connect**, then **Start**.
  </Step>

  <Step title="Authorize the certificate">
    As with local teleop, accept the self-signed certificate once. Tap **Authorize certificate** when prompted, or open `https://<tailscale-address>:8000` in the headset browser and continue past the warning. See [Authorize the TLS certificate](/operations/teleop#authorize-the-tls-certificate).
  </Step>
</Steps>

The session then works like local teleop, with the same controls and camera views.

## Drive from outside your tailnet (Funnel + TURN)

The steps above assume the operator can join your tailnet. To let someone drive without installing Tailscale, publish the robot on the internet with [Tailscale Funnel](https://tailscale.com/kb/1223/funnel). You need two pieces: Funnel carries the control connection, and a TURN server carries the camera video.

<Warning>
  Funnel puts the robot on the public internet, and the teleop connection has **no password**. Anyone with the URL can drive the arms. Turn Funnel on only during a session, and turn it off as soon as you're done:

  ```bash
  sudo tailscale funnel --https=443 off
  ```
</Warning>

### 1. Publish the control connection with Funnel

Funnel publishes only on ports 443, 8443 and 10000, and it handles TLS itself. Point it at the VR server's HTTPS port and tell it to skip the self-signed certificate check:

```bash
sudo tailscale funnel --bg https+insecure://localhost:8000
```

This publishes the control connection at `https://<your-machine>.tailXXXX.ts.net/` on port 443. Check it with `tailscale serve status`.

If your Tailscale version doesn't accept this command, use these two instead:

```bash
sudo tailscale serve --bg --https=443 https+insecure://localhost:8000
sudo tailscale funnel --bg 443 on
```

### 2. Add a TURN server for camera video

Camera video travels as a separate stream that doesn't go through Funnel. When the headset and the robot are on different networks, they need a public **TURN** server to relay the video. Use a hosted TURN provider, or run [coturn](https://github.com/coturn/coturn) on a machine with a public IP.

The repo includes a coturn setup for [Fly.io](https://fly.io) in [`deploy/turn/`](https://github.com/almond-bot/axol/tree/main/deploy/turn). Fly supports the UDP traffic TURN needs, which most hosting services don't. Follow [`deploy/turn/README.md`](https://github.com/almond-bot/axol/blob/main/deploy/turn/README.md) to launch your own server with a few `flyctl` commands.

Then set these variables on the Host Computer **before** you start teleop:

```bash
export AXOL_TURN_URL="turn:turn.example.com:3478,turns:turn.example.com:5349"
export AXOL_TURN_USERNAME="axol"
export AXOL_TURN_PASSWORD="your-turn-credential"
```

`AXOL_TURN_URL` is a comma-separated list of `turn:`, `turns:` or `stun:` URLs. Without these variables, an operator outside your tailnet can still drive the arms through Funnel, but sees no camera video. On a local network or a tailnet, leave them unset.

<Tip>
  Instead of exporting the variables in every shell, put them in a `.env.local` file in the directory you run `axol` from. `axol` loads it at startup. The file is ignored by git, so your TURN password stays out of version control.
</Tip>

### 3. Connect from the headset

In the VR app's **Connect** field, enter the Funnel address as an `https://` URL, or add `:443`. Otherwise the app uses the local default port, `8000`.

```
https://almond-zed-box.tailXXXX.ts.net
```

Funnel uses a valid public certificate, so there's no certificate to authorize. Press **Connect**, then **Start**.
