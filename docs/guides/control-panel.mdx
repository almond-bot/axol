title: "Web Control Panel"
description: "Connect to Axol from a browser, set up cameras and settings, and run every operation without a terminal."
---

The **web control panel** is a browser page for running Axol. Use it to connect to the robot, assign cameras, change settings, and run teleoperation, gravity compensation, data collection, dataset replay and policies. It is served by [`axol serve`](/cli/serve).

The sidebar on the left switches between its pages. On a phone, open it with the **☰** button.

| Page | What it is for |
|---|---|
| **Overview** | The robot's computer, Axol, Mantis and Jelly, and a card for each operation. |
| **Operations** | Pick an operation, fill in its fields and press **Start**. |
| **Datasets** | Watch recorded episodes and fix their task text. |
| **Settings** | Settings shared by every operation and every browser. |
| **Diagnostics** | Motor telemetry, tests and tuning. See [Diagnostics dashboard](/guides/diagnostics-dashboard). |
| **Logs** | The output of the latest operation. |

The robot's computer you are connected to shows at the bottom of the sidebar. Click it to connect to a different one.

## Open the control panel

With the [one-command install](/installation), the server already runs on the robot's computer (the one wired to the arms, with the ZED cameras attached). It starts at boot and restarts if it stops. Open [axol.almond.bot](https://axol.almond.bot) and connect to the host.

On a development install, start the server yourself:

```bash
axol serve
```

It prints a local and a LAN URL:

```
Axol control panel:
  Local : https://localhost:8001
  LAN   : https://192.168.1.50:8001
```

Open the **Local** URL on the robot's computer, or the **LAN** URL from another machine on the same network. Accept the self-signed certificate the first time. The panel is at `/control`, and it works on a phone or tablet too.

<Note>
  On a development install, build the local UI once (`cd web && npm install`, then `npm run build` for the `axol-vr-client` and `app` workspaces). Or skip the build and use the hosted UI at [axol.almond.bot](https://axol.almond.bot), which connects to your `axol serve`. See [Development install](/advanced/development-install#build-the-web-ui).
</Note>

<Tip>
  **Quickstart** at the bottom of the sidebar has commands to copy for installing the CLI and starting the server.
</Tip>

## Connections

The **Overview** page has four tiles: **Axol Host**, **Axol**, **Mantis** and **Jelly**. Each has a status dot. Click a tile's title to open its [settings](#settings). The **Axol Host** tile opens the general settings.

**Choose the device.** Every operation runs on either Axol or Mantis. The chosen tile shows **selected**, and the other shows **Select**.

- With Mantis selected, only **Teleoperation** and **Collect data** are offered.
- The choice is saved on the host, so every browser sees the same one.
- You can't change it while an operation is running.
- If only one of Axol or Mantis is plugged in, the panel selects it for you.

<Warning>
  Closing the browser tab, or disconnecting from the host, does **not** stop anything. The robot connection and any running operation keep going in `axol serve`. Press **Stop** to end an operation.
</Warning>

### Axol Host

The **Axol Host** is the computer running `axol serve`. Press **Connect** on its tile and enter the host's IP address (port `8001` is assumed). Click the field to pick from the last five hosts this browser connected to. If the host doesn't answer within a few seconds, the dialog says it can't reach the host.

Once connected, the tile shows the host's name and its installed version (for example `axol v0.1.2`). Teleoperation and gravity compensation need nothing else.

The connected tile has three buttons:

| Button | What it does |
|---|---|
| **Restart** | Reboots the robot's computer after you confirm. Reconnect when it is back, usually in under a minute. |
| **Shut down** | Powers the robot's computer off after you confirm. You need physical access to turn it back on. |
| **Disconnect** | Disconnects this browser only. The server, the robot and any running operation keep going. |

**Restart** and **Shut down** wait until no operation is running and no update is installing. On a development install they need passwordless `sudo`, or the host reports that it couldn't restart and stays up.

#### Updates

When a newer [release](https://github.com/almond-bot/axol/releases) is available, a banner at the top of every page shows the version change and links to the release notes. Nothing updates until you press **Update**.

1. Stop any running operation. **Update** is disabled while one runs.
2. Press **Update**. The button shows each step: `Upgrading…`, `Installing packages…`, `Restarting…` or `Rebooting host…`.
3. Wait for the panel to reconnect on the new release. Some updates reboot the host.

If a required step fails, the error names it. Press **Update** to try again. Optional steps, such as Lighthouse tracking, show a warning instead of stopping the update. Each step's full output is in `/var/log/almond-axol/` on the host.

The banner also warns when the panel and the host run different versions. This happens with an old browser tab or an outdated local UI build. Update the host, or rebuild the local UI.

#### Axol version

Axol comes in several versions with the same arms. The version tells Axol where its mount is, so the arms don't hit it, and sets the joint limits.

When Jelly is attached, Axol uses **Axol on Jelly** automatically. This applies while Jelly's wheel or lift adapter is plugged in and not switched off under **Jelly settings → Wheels & lift**. Otherwise, pick what Axol is mounted on under **Mount** at the top of **Axol settings → Robot**, then press **Save**:

| Version | Mount |
|---|---|
| **Axol Legacy** | The original model, and the default. |
| **Axol Standalone** | No mount. Axol is bolted to your own table or fixture. |
| **Axol on Ox Cart** | On the Ox Cart's lift column, with the lift fully raised. |
| **Axol on Owl Mount** | On the Owl Mount's column. |

You can preview any card by hovering it. You can pick one only while Axol is connected.

Until a version is saved, the **Overview** page shows a **What is Axol mounted on?** card, and runs that drive the arms list *Choose what Axol is mounted on* under [Before you can start](#before-you-can-start). Sim runs and runs with the arms off don't need it.

On Axol on Jelly with the parcel gripper (**Gripper** in **Axol settings → Robot**), the panel uses the parcel gripper's model. To force a version, set `kinematics.robot_model` under **General settings → Advanced → Kinematics**, or pass `--kinematics.robot_model` on the CLI.

### Axol and Mantis

The panel finds the CAN adapters plugged into the host and connects the selected device automatically. On a new hub, it first identifies each adapter (Axol arm, Mantis rig, Jelly wheels or Jelly lift) and names it, the same way [`axol can.setup`](/cli/can-setup) does.

If the automatic connection fails twice, press **Connect** on the tile. After you press **Disconnect**, the panel doesn't reconnect that hardware automatically until you press **Connect** or change the selection.

**If an adapter isn't identified.** This happens when the hardware was off while the server started. Power on the hardware, then press **Connect** or **Retry CAN identification**. If that still fails, run `axol can.setup` in a terminal.

To change which CAN interface each side uses, go to **Axol settings → Robot** or **Mantis settings → CAN**.

**Motor status.** While no operation runs, the panel checks every motor once a second: all 16 Axol motors, or the two Mantis grippers. Each motor is a square on the tile. Hover a square to see its status and temperature.

| Square | Meaning |
|---|---|
| Green | Reachable and reporting no error. |
| Red | Unreachable or reporting a fault. Operations on that device can't start until you fix it. Sim teleop still works. |
| Grey | Unknown, because a running operation is using the bus. |

**If motor power is cut.** If you cut motor power during a run, for example at the power supply, the run stops with `motor power lost`. Usually the panel then releases the robot without any action from you. If a motor still answers with torque on, the panel shows **Re-check motors**. Cut motor power, then press it.

**Mantis.** Press **Select** on the Mantis tile. See [Mantis Hardware](/mantis/hardware) for the rigs and hub.

- **Teleoperation** drives the grippers from the rig triggers. It needs only CAN, with no tracking.
- **Collect data** uses the pose source set under **Mantis settings → Tracking**. See [Mantis Tracking](/mantis/tracking).
- Mantis can't run **Run policy** or **Collect DAgger**.

### Jelly

The **Jelly** tile has a row each for the wheels and the lift, each with a connect button. Jelly is driven together with Axol, so it isn't part of the device choice.

While the lift is connected, the tile shows the battery charge and pack voltage. The icon is green above 25%, amber at 25% and below, red at 10% and below, and blue while charging.

- A reading with `~` (for example `~40%`) was measured while Jelly was moving, so it reads low.
- While an operation uses the bus, the last reading stays dimmed. Hover it to see its age.
- The figure is a rough range, not an exact gauge. For an exact charge, use the batteries' LiTime Bluetooth app.

From Python, [`Jelly.battery`](/api/robot#jelly) returns the same estimate.

## Settings

Settings that apply to every run live on the **Settings** page. Switch between **Axol**, **Mantis**, **Jelly** and **General** at the top of the page, or click a tile's title on the **Overview**.

**Axol settings**

| Tab | What's in it |
|---|---|
| **Cameras** | Camera previews and the Axol camera layout. See [Cameras](#cameras). |
| **Robot** | **Mount** ([Axol version](#axol-version)), arm stiffness, CAN channels, gripper type and limits, gravity-comp damping and rate, the contact stops, and the **Axol arms** switch. |
| **Teleop & VR** | Teleop rate, position and rotation multipliers, **Hold grips to engage** and **Park to zero on stop**. |
| **Rest pose** | A 3D editor with a slider per joint. The arms start from and return to this pose in teleop and data collection. |
| **Kinematics** | The **IK solver** (`jax` by default, or `mink`, see [Mink IK](/operations/mink)) and its main weights. |

**Contact stops.** The **Return-to-rest contact stop** is always on: it stops a return to rest that runs into something and leaves the arms limp. The **Teleop contact stop** and **Policy contact stop** are off by default. Turn one on to stop the arms and leave them limp when they push on something during teleop or a policy run. Raise a threshold if normal motion trips it.

**Axol arms.** Turn it off to drive only Jelly from the headset. Axol doesn't need to be connected then.

**Mantis settings**

| Tab | What's in it |
|---|---|
| **Tracking** | The pose source (Quest, Lighthouse or Ultimate) and its setup steps. See [Mantis Tracking](/mantis/tracking). |
| **Triggers** | **Left trigger full squeeze** and **Right trigger full squeeze**, which scale each trigger to a full close (default `1.0`). See [Testing the triggers and grippers](/mantis/hardware#testing-the-triggers-and-grippers). |
| **Cameras** | The Head, Left Mantis and Right Mantis camera layout, kept separate from Axol's. |
| **CAN** | The left and right Mantis CAN interfaces (`can_mantis_l` and `can_mantis_r` by default). Swap the two values to swap sides without moving cables. |

**Jelly settings**

| Tab | What's in it |
|---|---|
| **Wheels & lift** | **Jelly wheels** and **Jelly lift**. Turn one off to leave that part of Jelly still, even when it is attached. |
| **Parameters** | Drive speeds and other Jelly settings. |

**General settings**

| Tab | What's in it |
|---|---|
| **Quest** | The [Quest over USB](#quest-usb) link and **Keep awake**. |
| **Recording** | Dataset fps, video codec, dataset root, push to the Hugging Face Hub, and the Rerun viewer address. |
| **Inference** | Device, inference server host and port, episode length, and action chunking. |
| **System** | Log level. |
| **Advanced** | Every other setting, grouped by subsystem, with a search box. Per-joint gains show as one table per arm. |

Recording fps above 60 raises the cameras' capture rate to match. The ZED X supports rates above 60 only at `SVGA`.

**Saving.** Changes stay in your browser until you press **Save** (or **Discard**). They are kept while you visit other pages, and a dot next to **Settings** in the sidebar shows that some are unsaved. Settings are saved on the host in `~/.almond/settings.json`, so every operation and every browser uses the same values. The [`axol` CLI](/cli/configuration#the-shared-settings-file) and the [SDK](/api/robot#shared-settings) read the same file. A field you haven't set shows its default in grey, and a changed field has a reset button.

**Export** and **Import** at the bottom of the settings save the whole settings file as JSON, or load one. Use them for backups or to copy settings to another robot. The [Settings File](/guides/control-panel-settings) page describes the file. Each operation's **Config Parameters** page, such as [Teleoperation](/operations/teleop-config), lists every setting with its default.

### Cameras

Data collection and policies need ZED cameras on the host. Assign Axol's cameras under **Axol settings → Cameras** (overhead, left arm, right arm). Assign Mantis cameras under **Mantis settings → Cameras** (Head, Left Mantis, Right Mantis). The two layouts are saved separately.

Each panel lists the cameras plugged into the host, with serial number, type (stereo ZED X or mono ZED X One), model and a preview frame. Use the preview to tell which camera is which.

- Press **Refresh** to list the cameras again and update the previews.
- Press **Restart camera service** after you plug in or unplug a GMSL camera.
- Previews aren't available while an operation is using the cameras.

**Stream and Record.** Each layout has two outputs:

| Output | Where it goes |
|---|---|
| **Stream** | The live video in the VR headset during teleop and data collection. |
| **Record** | The video saved in the dataset. **Run policy** and **Collect DAgger** also feed the policy at this resolution, so it matches the training data. |

Each output has a resolution setting (`SVGA`, `HD1080` or `HD1200`) or **Off**. Each camera has separate **Stream** and **Record** switches. A stereo camera has **L** and **R** checkboxes for each eye instead. This lets you, for example, stream both eyes of the overhead camera for depth and record only one.

A stereo overhead camera with both eyes recorded is saved as two cameras, `overhead_left` and `overhead_right`. A single eye is saved under the slot name, like a mono camera.

**What each operation needs.**

- **Collect data**, **Run policy** and **Collect DAgger** need at least one camera with **Record** on. A camera set to stream only doesn't count.
- They also check that every assigned camera is plugged in, and name any missing serial. Reconnect it, then press **Refresh** (or **Restart camera service**).
- **Teleoperation** streams whatever is set up and is never blocked by cameras.

The Mantis **Head** slot starts unassigned. A slot you leave unassigned is off.

### Quest USB

The **Quest** tab under **General settings** runs the optional [Quest over USB](/guides/quest-over-usb) link. It sends the controller poses over a USB cable for lower latency. Camera video still uses the network.

1. Plug the Quest into the robot's computer with a USB-C cable.
2. The first time, put the headset on and accept **Allow USB debugging?**.
3. The link connects automatically and shows *Controller over USB*. Press **Connect** to retry if it doesn't.

If the cable is pulled, poses continue over Wi-Fi with no reconnect.

For [headless](/guides/quest-headless) use, press **Keep awake** with the headset plugged in. The headset keeps the VR session running while it sits on a table. **Allow sleep** turns normal sleep back on, and so does rebooting the headset.

## Operations

Open the **Operations** page, or click an operation's card on the **Overview**. Pick an operation from the list, fill in its fields, and press **Start**. The panel asks only for values that change between runs, such as a dataset name or a policy path. Everything else is in [Settings](#settings).

- Hover the **ⓘ** next to a field for its description.
- Some fields offer a list to pick from, such as the datasets on the host. You can still type your own value.
- A few fields accept only values from their list. **Start** stays disabled with *Pick &lt;field&gt; from the list* until you pick one.
- Your browser remembers these values for next time.

| Operation | Needs | What it does |
|---|---|---|
| **Teleoperation** | Axol, Mantis, or sim | Drive Axol from a Quest. With Jelly attached, the thumbsticks drive Jelly too. With Mantis selected, drive the rig grippers from their triggers. Turn on **sim** to drive a simulated Axol in the browser, and pick its version under **Sim robot**. See [Teleoperation](/operations/teleop#run-it). |
| **Gravity compensation** | Axol | Hold the arms weightless so you can move them by hand. |
| **Waypoints** | Axol or sim | Teach a path by hand and replay it. See [Waypoints](#waypoints). |
| **Collect data** | Axol or Mantis, and cameras | Record episodes into a LeRobot dataset. Pick an existing dataset under **repo id** to add to it. See [Data collection](/operations/data-collection#run-it). |
| **Replay dataset** | Axol | Play a recorded episode on the arms, then return to rest. Turn on **loop** to repeat until **Stop**, and **interpolate** to smooth playback. |
| **Run policy** | Axol and cameras | Run a LeRobot policy on the robot or on an [inference server](/cli/inference-server). Choose policy type `custom` to run [your own model](/operations/custom-policy), which needs no checkpoint path. |
| **Collect DAgger** | Axol and cameras | Run a policy and correct it from VR, recording both. A `custom` policy needs `hold_to_intervene=true`. See [`collect-dagger`](/cli/collect-dagger). |

<Note>
  Recordings go to the **Dataset root** setting. By default this is `~/.cache/huggingface/lerobot` of the account that ran the installer, so the panel and the CLI see the same datasets.
</Note>

### Request data collection

Almond can collect labeled data for your task and deliver it in LeRobot format. The **Teleoperation** and **Collect data** pages have a card for it.

1. Press **Request data collection**.
2. Enter the hours of usable data you want. The form shows the hourly price and the total.
3. Describe the task: what the robot should do, with which objects, and what counts as done.
4. Add an example of the task: a link to a video, or a Hugging Face dataset of sample episodes.
5. Press **Continue to payment** and pay on Stripe's checkout page.

You pay for the hours you request. If Almond delivers fewer usable hours, Almond refunds the difference. After you pay, Almond contacts you by email to plan the collection.

The request needs an internet connection on the computer running the browser. To hide the card, press **×** on it.

### Waypoints

1. Start **Waypoints**. The arms go into gravity compensation.
2. Move the arms by hand and press **Record waypoint** at each pose. Use **Undo last**, **Clear all** and the gripper buttons as needed.
3. Once you have two or more waypoints, press **Play** to replay the path as straight-line moves. **Stop playback** stops it.

Lower the **Speed scale** slider to try a new path slowly. Turn on **sim** to preview a saved path in the browser. See [`waypoints`](/cli/waypoints).

### Before you can start

**Start** stays disabled until the operation has what it needs. A **Before you can start** list says what is missing, for example:

- *Connect Axol*
- *Choose what Axol is mounted on* (see [Axol version](#axol-version))
- *Fix motor fault*, followed by the motor and the fault
- *Assign a camera and enable Record in Axol settings → Cameras*
- *Identify left + right Lighthouse trackers*

Fix tracker problems under **Mantis settings → Tracking** ([Mantis Tracking](/mantis/tracking)). Tracker-to-TCP transforms are a [file on the host](/cli/tracker#transform-file). Tracking only matters for Mantis data collection. Mantis teleop needs only CAN.

### Logs and stopping

The newest line of output shows below the operation. If the operation stops with an error, that line turns red and shows the error. Click it, or open **Logs** in the sidebar, to see the full output, including messages from the ZED SDK, GStreamer and CUDA.

- The log follows new lines while you are scrolled to the bottom. Scroll up to read, and press the arrow button to jump back.
- The download button saves the log to a `.log` file to attach to a bug report.

While an operation runs, every other page shows its name at the top right, and **Operations** in the sidebar has a green dot. The **Overview** also shows it with a **Stop** button.

Press **Stop** to end an operation. The badge shows **Stopping…** until the operation has shut down, then the robot returns to idle. You can disconnect Axol only when no operation is running.

## Operator view

During **Teleoperation**, **Collect data** and **Collect DAgger**, the panel shows the same camera feeds as the headset. You can watch the robot's view without wearing the headset. The [camera layout](#cameras) decides what streams. Sim runs and runs with **Axol arms** off show no feeds.

Press the fullscreen button on the camera feeds to fill the screen. Press **Esc** or **Exit fullscreen** to leave. If the feeds never connect, press **Authorize** to accept the stream's self-signed certificate, the same one-time step as in the [VR app](/guides/vr-interface).

## Episode controls

While **Collect data**, **Run policy** or **Collect DAgger** runs, an **Episode control** box appears in the operation card. It shows the phase (Ready, Recording, Saving, Resetting and so on), the episode number and the number saved. Every connected browser sees the same state. To end the whole session, press **Stop**.

Some operations also show a setup card with an instruction, a list of items and a layout grid, for example the scene to set up next. **Hide setup** and **Show setup** fold it away.

**Run policy and Collect DAgger**

| Button | What it does |
|---|---|
| **Start episode** | Start the next rollout once the scene is reset. |
| **Save** | Save the episode. Then press **Start episode** for the next one. |
| **Discard** | Drop the episode. The arms go limp so you can move them out of the way by hand. Then press **Return to rest**. |
| **Return to rest** | Send limp arms back to rest from where they are. It appears after **Discard**, or when the arms hit something (phase **Contact**). Clear the arms by hand first. |

These match the `s` and `r` keys and the Enter prompts of [`run-policy`](/cli/run-policy). To correct a policy from VR in **Collect DAgger**, see [Intervening](/operations/dagger#intervening).

**Collect data**

| Button | What it does |
|---|---|
| **Start recording** | Start the next take after a 3-second countdown, so you can pick up the controllers. Press again to cancel. |
| **Save episode** | End the take and save it, like **A** in the headset. Press twice to confirm. |
| **Discard episode** | End the take and drop it, like **X** in the headset. Press twice to confirm. |
| **Return to rest** | Appears when the arms hit something and went limp (phase **Contact**). Clear the arms by hand, then press it, or press **X** on the controller. |

If a take ends without being saved, the box shows the reason in red until the next take starts.

With Axol or Mantis on Quest, the VR controllers also work, and whichever input comes first wins. With Mantis on Lighthouse or Ultimate, no headset is needed:

- Squeeze and release both rig triggers together to engage tracking and start a take. **Start recording** works only after the rig is engaged.
- While recording, press either trigger three times to save, or four times to discard.

## Datasets

The **Datasets** page plays the datasets on the host. Pick a dataset and an episode. All of the episode's cameras play side by side with one play button and scrub bar.

The menu next to the scrub bar sets the playback rate: **15 fps** (the default), **30 fps** or the full recorded rate. Full rate with four cameras needs about 85 Mbps, more than most Wi-Fi or Tailscale links carry. Nothing downloads until you press play.

**Rename a task.** Type the new task text, or pick one of the dataset's tasks, and press **Save task**. The change is written into the dataset, so replay and training see the new text.

During a recording session, the page follows the dataset being recorded and selects each take once it is saved. You can review earlier takes and fix a mistyped task without stopping the session.
