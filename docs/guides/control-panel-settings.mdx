`~/.almond/settings.json` on the robot's computer holds the robot's settings. Every tool uses it:

- The [control panel](/guides/control-panel#settings) edits it and applies it to every operation it starts. **Export** and **Import** in the panel save and load this file.
- The [`axol` CLI commands](/cli/configuration#the-shared-settings-file), such as `axol teleop`, `gravity-comp` and `collect-data`, read it by default.
- The [SDK constructors](/api/robot#shared-settings) (`Axol()`, `VRTeleop()`, `Jelly()`, `Mantis()`) build their default configs from it.

## Which value wins

When a value is set in more than one place, the later one in this list wins:

1. The built-in defaults.
2. The settings file.
3. A `--config_path` file.
4. CLI flags.

On the CLI, `--no_settings` skips the file and `--settings_path PATH` reads a different one. In the SDK, a config or channel argument you pass overrides the setting.

## Layout

The file has one object per section. It stores only the values you have changed. Anything missing uses the default.

```json
{
  "version": 2,
  "axol": {
    "left_stiffness": 0.8,
    "has_gripper": true,
    "left": { "elbow": { "kp": 60 }, "gripper": { "torque_limit": 0.4 } }
  },
  "teleop": { "frequency": 240, "rest_pose_left": [-0.15, 0, 0, 0.31, 0, 0, -0.15] },
  "kinematics": { "pos_weight": 100 },
  "robot": { "left_channel": "can0", "right_channel": "null" },
  "gravity": { "kd": 0.5 },
  "recording": { "fps": 30, "root": "/data/lerobot" },
  "cameras": { "serials": { "overhead": "12345" } }
}
```

The `axol`, `teleop`, `kinematics`, `jelly` and `vr_server` sections have the same fields as the matching configs. They use the same names as a teleop [`--config_path`](/cli/configuration) file, the operation config pages and the SDK:

- `axol` is the [robot config](/operations/teleop-config#robot).
- `teleop` is the [teleop session](/operations/teleop-config#teleop).
- `kinematics` is the [kinematics config](/operations/teleop-config#kinematics).
- `jelly` is the [Jelly config](/operations/teleop-config#jelly).
- `vr_server` is the VR server.

You can set any field in these sections. The panel shows the common ones as controls and the rest under **Advanced**. Each value applies to every operation that uses it.

| Section | Contains | Used by |
|---|---|---|
| `axol` | Arm stiffness (`left_stiffness`, `right_stiffness`), `has_gripper`, `gripper` (`parallel` or `parcel`), per-joint gains and masses, and gripper limits such as `left.gripper.torque_limit`. | Every operation |
| `teleop` | `frequency`, `position_multiplier`, `rotation_multiplier`, `hold_to_engage`, `park_to_zero`, the rest pose (`rest_pose_left`, `rest_pose_right`) and the contact thresholds. | Teleop, data collection, DAgger. Some fields also apply to run policy and replay. |
| `kinematics` | `mount` (`classic`, `standalone`, `ox_cart` or `owl`), `robot_model`, the IK weights and `max_joint_delta`. | Teleop, data collection, DAgger |
| `jelly` | `wheels` and `lift` (the **Jelly wheels** and **Jelly lift** switches), `max_speed` and the other drive settings. | Teleop, data collection, DAgger |
| `vr_server` | The VR server's `port` and other settings. | Teleop, data collection, DAgger |
| `lerobot` | LeRobot `robot_config` fields such as `observe_torques`, `observe_cartesian`, `id` and `calibration_dir`. | Data collection, DAgger, run policy, replay |
| `lerobot_teleop` | LeRobot `teleop_config.id` and `teleop_config.calibration_dir`. | Data collection, DAgger |
| `robot` | `left_channel` and `right_channel`, the arms' CAN interfaces. `"null"` turns an arm off. | Every operation, diagnostics dashboard |
| `gravity` | `kd` and `rate_hz` of gravity compensation. | Gravity compensation, waypoints |
| `mantis` | `source` (`lighthouse`, `ultimate` or `quest`), `quest_tracker_key`, and the Mantis CAN channels (`can_mantis_l` and `can_mantis_r` by default). | Mantis data collection and teleop |
| `recording` | `fps`, `replay_fps`, `vcodec`, `root`, `push_to_hub`, `rerun_ip` and `rerun_port`. | Data collection, DAgger, run policy, replay |
| `inference` | The [run policy](/operations/run-policy-config) settings, such as `device`, `server_host`, `server_port` and `episode_time_s`. | Run policy |
| `system` | `hardware_profile` (`axol` or `mantis`, the device chosen in the panel) and `log_level`. | Every operation |
| `cameras` | The camera layouts set in the panel. | Teleop, data collection, DAgger, run policy |

`kinematics.mount` is what Axol is mounted on when Jelly isn't attached, set by **Choose your Axol** in the panel. `kinematics.robot_model` forces a version: any `mount` value, or `mobile` for Axol on Jelly. Leave it unset to use Axol on Jelly whenever Jelly is enabled, and `mount` otherwise. See [Axol version](/guides/control-panel#axol-version).

## Version 1 files

A version 1 file has a flat `values` map with keys such as `robot.left_stiffness`, and an `advanced` map. Axol reads it and saves it in the layout above the next time settings are saved. You can import a version 1 file into the panel too.
