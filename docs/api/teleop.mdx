Connects a VR headset to Axol, or to the simulator, for teleoperation. Each VR frame goes through four stages before it reaches `motion_control()`:

1. A lag-compensated low-pass filter on the raw poses.
2. An IK solve, in a separate process so it never blocks the asyncio event loop.
3. Exponential smoothing of the IK output.
4. A trapezoidal velocity and acceleration limit.

```python
from almond_axol.teleop import VRTeleop, VRTeleopConfig
```

```python
import asyncio
from almond_axol.robot import Axol
from almond_axol.teleop import VRTeleop

async def main():
    async with VRTeleop(Axol()) as teleop:
        await teleop.run()  # blocking; Ctrl+C to exit

asyncio.run(main())
```

```python
VRTeleop(
    robot: RobotBase,
    *,
    config: VRTeleopConfig | None = None,             # None: teleop.* shared settings
    kinematics_config: KinematicsConfig | None = None, # None: kinematics.* shared settings
    vr_server_config: VRServerConfig | None = None,    # None: vr_server.* shared settings
    jelly: Jelly | None = None,
)
```

Each config you leave as `None` is loaded from the shared settings file, `~/.almond/settings.json`, over the built-in defaults. The [control panel](/guides/control-panel-settings) edits this file and `axol teleop` reads it, so an SDK session uses the same rest poses, multipliers, IK weights and VR port. Pass a config to override it. See [Shared settings](/api/robot#shared-settings).

Use `step()` instead of `run()` to run teleoperation inside your own control loop:

```python
async with VRTeleop(axol) as teleop:
    while True:
        left_q, right_q = teleop.step()  # returns latest smoothed (8,) arrays
        # ... custom logic ...
        await asyncio.sleep(1 / 120)
```

To show camera feeds in the headset, call `VRTeleop.set_video_sources()` inside the session. It forwards the sources to the VR server's WebRTC relay, which needs the GStreamer NVENC stack from [`axol gst.install`](/cli/gst-install). Each value is a connected `ZedCamera`, or any object with `width`, `height`, `fps` and `wait_next()`. See [`almond_axol.vr`](/api/vr#camera-video-to-the-headset).

```python
async with VRTeleop(axol) as teleop:
    teleop.set_video_sources({"overhead": cam})
    await teleop.run()
```

The [`teleop`](/cli/teleop) CLI command is the command-line equivalent. Its `--cameras` flag sets up the ZED cameras for you.

<Note>
  `set_video_sources()` runs the WebRTC relay in the teleop process. `VRTeleop.set_video_manager()` instead runs camera capture, encoding and WebRTC in a separate process (`almond_axol.video.video_proc.VideoRelayProcess`), so video work can't slow the control loops. The CLI uses `set_video_manager()`. Both send the same video to the headset.
</Note>

## `VRTeleopConfig` fields

Joint velocities and accelerations are set in rad/s and rad/s². The defaults below also give them in rev/s, the unit the control panel and headset show.

### Control loop and filtering

| Field | Default | Description |
|---|---|---|
| `frequency` | `120` Hz | Control loop rate of `run()`. Also sets the waypoint density of return-to-rest moves. |
| `ik_frequency` | `120` Hz | Rate at which VR frames are sent to the IK solver. The control loop interpolates between solutions. |
| `teleop_max_vel` | `2π` rad/s (1 rev/s) | Joint velocity cap while tracking. Live setting (**Arm speed**). |
| `teleop_max_accel` | `3π` rad/s² (1.5 rev/s²) | Joint acceleration cap while tracking. |
| `engage_max_vel` | `0.2π` rad/s (0.1 rev/s) | Velocity cap at the first engage after a reset. It ramps up to `teleop_max_vel` over `engage_duration`. |
| `engage_duration` | `1.0` s | Time for the velocity cap to ramp from `engage_max_vel` to `teleop_max_vel`. |
| `ik_alpha` | `0.3` | Smoothing factor on the IK output. `1.0` turns smoothing off. |
| `pose_cutoff` | `2.5` Hz | Cutoff of the low-pass filter on raw VR poses, which rejects hand tremor before IK. |
| `position_multiplier` | `1.0` | Scale from hand position to end-effector position. Above `1` extends reach. Live setting (**Reach scale**). |
| `rotation_multiplier` | `1.0` | Scale from hand rotation to end-effector rotation. Above `1` turns the arm further than your wrist. |
| `record` | `None` | File prefix for the teleop flight recorder, which `axol diag.teleop-jitter` reads. |

`record` writes each pipeline stage to its own file: `<prefix>_ik.npz`, `<prefix>_cmd.npz`, `<prefix>_meas.npz` and `<prefix>_rt.npz`. The `rt` file holds the realtime core's 240 Hz motor commands, control terms, timing and feedback. Each file keeps the most recent engage-to-disengage segment.

### Engage and reset

| Field | Default | Description |
|---|---|---|
| `hold_to_engage` | `False` | `True` makes each grip a dead-man switch: its arm tracks only while the grip is held. Live setting (**Hold to engage**). |
| `reengage` | `"clutch"` | What a grip does when it re-engages an arm: `"clutch"` or `"ramp"`. See [Re-engaging](#re-engaging). Live setting (**Re-engage**). |
| `reengage_ramp_speed` | `0.15` m/s | Speed of the `"ramp"` blend. A 30 cm gap takes at least 2 s. |
| `reengage_ramp_min_s` | `0.75` s | Shortest `"ramp"` blend, so a small correction is eased rather than stepped. |
| `reset_speed` | `0.2π` rad/s (0.1 rev/s) | Average velocity of the joint that moves farthest during return-to-rest. The peak is 1.5 times this with the default IK solver. |
| `reset_min_duration` | `1.5` s | Shortest return-to-rest move, so an arm near rest doesn't snap home. |
| `rest_pose_left` / `rest_pose_right` | near zero | Return-to-rest target for each arm, shape `(7,)` in `ARM_JOINTS` order. |

### Box mode

| Field | Default | Description |
|---|---|---|
| `gripper` | `None` | Which gripper is fitted: `"parallel"` or `"parcel"`. `None` follows the robot's `AxolConfig.gripper`. |
| `box_mode` | `False` | Start in [box mode](/guides/vr-interface#box-mode). Live setting (**Box mode**). |
| `box_lead_hand` | `"right"` | Which controller leads the pair when box mode turns on. The other grip can take over the lead. Live setting. |
| `box_grasp` | `"straight"` | Starting grasp. `"straight"` points the fingers forward, and `"flush"` turns each gripper inward by `box_flush_deg`. Live setting (**Box grasp**). |
| `box_flush_deg` | `39`° | How far the `"flush"` grasp turns each gripper inward, about the front edge of the parcel plate. Live setting (**Angled yaw**). |
| `box_face_left` / `box_face_right` | `"auto"` | Which side of each gripper (`"+x"` or `"-x"`) faces the box. `"auto"` picks the side that needs the smaller wrist turn. Live settings (**Left face**, **Right face**). |
| `box_grip_tilt` | `0`° | Fixed inward yaw trim of each gripper. Positive turns the fingertips toward the box, negative splays them out. |
| `box_width_speed` | `0.08` m/s | Rate at which the right thumbstick's forward and back changes the grip width at full deflection. |
| `box_width_min` / `box_width_max` | `0` / `0.70` m | Limits on the grip width, measured between the contact faces. The minimum is raised where needed so the gripper bodies never touch. The parcel gripper's faces can close all the way together. |
| `box_align_duration` | `1.5` s | Time to blend the grippers into the parallel pair when box mode engages or the grasp changes. |
| `box_elbow_out` | `30`° | How far out the elbows are held, from `0` (straight down) to `90` (level). Live setting (**Elbows out**). |
| `box_elbow_weight` | `10` | IK weight that holds the elbows at `box_elbow_out`. `0` turns it off, and `box_elbow_out` then does nothing. |
| `box_wrist_torque` | `5` Nm | Cap on the spring torque of `wrist_2` and `wrist_3` in box mode, which keeps the wrist motors from overheating. `0` turns it off. |
| `box_squeeze_force` | `0` N (off) | Cap on how hard each arm clamps the box. Live setting (**Squeeze force**). |
| `box_squeeze_lean` | `1` | Scale on the squeeze lean, which angles each gripper into the box as the clamp builds. `0` turns it off. Live setting (**Squeeze lean**). |
| `box_squeeze_trim` | `5`° | Most inward yaw the squeeze trim may add while the grippers press. `0` turns it off. Live setting (**Squeeze trim**). |
| `box_squeeze_torque` | `0` Nm (off) | Hard cap on the spring torque of `shoulder_2` and `shoulder_3` in box mode. Live setting (**Squeeze cap**). |

Box mode needs the [parcel gripper](/guides/vr-interface#box-tool). Set the gripper on the robot with `--axol.gripper`, not with this config. A `gripper` value that disagrees with the robot's is overridden with a warning, and with no robot to follow (`Sim`), `None` means `"parallel"`. With the parallel gripper:

- every `box_*` live setting is hidden,
- `box_mode` starts off, with a warning,
- `VRTeleopCore.set_box_mode(True)` raises `ValueError`.

In box mode one grip drives both arms by position and rotation. The pair follows the hand's movement, and the hand's yaw, pitch and roll since the engage turn the pair about its center, scaled by `rotation_multiplier`. Engaging into box mode starts the pair level. A re-snap inside box mode, such as a lead handover, a re-lead after a freeze or a grasp switch, keeps a tipped pair's tilt while both grippers still sit in its frame.

The thumbsticks drive [Jelly](/guides/vr-interface#jelly) as usual throughout box mode, led or frozen. While a grip leads:

- The right thumbstick's forward and back changes the grip width. Forward is wider. Jelly doesn't read this axis.
- A quick tap of either thumbstick click toggles between the two grasps. A tap is released within 0.3 s, with the other stick up.
- A click held longer than that runs Jelly's lift, from then until release.

`VRTeleopCore.box_stick_frame()` splits the clicks into taps and holds, and hands Jelly a copy of the frame with the clicks cleared until a hold is recognised. A tap queues `set_live("box_grasp", "toggle")`.

Box mode switches from the headset's **Box** button, both thumbstick clicks together, the control panel, or `VRTeleopCore.set_box_mode()`. The switch engages right away: into box mode led by `box_lead_hand`, or out of it with both arms. If no VR frame arrives within a second of the switch, or a return to rest ends box mode, nothing engages.

#### The squeeze

When you jog the grip width past the box, the arms' joint springs turn the extra distance into clamp force, about 6 N per centimetre. These settings shape the clamp:

- **Squeeze force** (`box_squeeze_force`) caps the clamp force per arm, at any pose. Try `8` N. With it off, nothing limits the clamp. Past about 39 N a side, `wrist_2` saturates at the default `box_wrist_torque` and the tip can unload onto the facet.
- **Squeeze lean** (`box_squeeze_lean`) yaws each gripper inward about 1.3° per centimetre of clamp depth, so the tip and root of the gripper press evenly. Raise it if the tip lifts as you squeeze. Lower it if the face near the wrist lifts.
- **Squeeze trim** (`box_squeeze_trim`) adds inward yaw from the measured gripper angle until each face sits parallel to the box. It corrects for backlash and flex that the lean doesn't model, and acts only once the pair has held still for 0.3 s.
- **Squeeze cap** (`box_squeeze_torque`) is a hard torque cap on the two shoulder joints. It also slows any move toward the other arm, so the pair can skew. Leave it at `0` unless you need it.

The squeeze settings and `box_wrist_torque` work on hardware only. The IK worker reports the clamp force and trims in `IKWorker.pair_status()` as `squeeze`, `trim` (mean) and `trims` (`[left, right]`). While the grippers press, the teleop log prints a `box clamp:` line once a second.

### Mantis

| Field | Default | Description |
|---|---|---|
| `absolute_mode` | `False` | Mantis mapping. Fits one fixed world-to-robot-base transform at the two-control engage gesture, then maps poses 1:1 in that frame. |
| `base_height` | `None` | Robot base height in the tracker's world. `None` derives it from the two held start poses. |
| `tcp_transform_left` / `tcp_transform_right` | `None` | Tracker-to-gripper transform `[x, y, z, qx, qy, qz, qw]`, in metres. |
| `tracker_key` | `None` | Quest controller transform key, `quest:<WebXR-profile>:grip`. Lighthouse and Ultimate trackers ignore it. |
| `quest_controller_profile` / `quest_pose_space` | `None` | Expected Quest controller profile and pose space, normally derived from `tracker_key`. On a mismatch, that side stops tracking until you recover it. |
| `urdf_viewer_world_aligned` | `None` | Whether the headset shows the robot overlay in the tracker's world. `None` means true for Quest and false for Lighthouse and Ultimate. |

A TCP transform must have seven finite numbers, a translation of at most 1 metre, and a nonzero quaternion. Production Mantis collection also requires it to match the active tracker's entry in `~/.almond/mantis/tcp_transform.json`, or a verified factory constant. Lighthouse and Ultimate trackers take their left and right bindings (`survive:<id>`, `ultimate:<mac>`) from the tracker config instead of `tracker_key`. A saved Ultimate entry stops counting if its pose convention changes.

Set `urdf_viewer_world_aligned` to true for a Lighthouse or Ultimate tracker only after you have registered its origin and heading to the Quest's world.

## Engage behavior

- From rest, press both grips together to engage both arms.
- Once engaged, a grip click toggles its arm between tracking and frozen. A frozen arm holds its pose and grasp while the other keeps tracking.
- With `hold_to_engage`, an arm tracks only while its grip is held, from rest too. Releasing the grip freezes that arm. If tracking stops while a grip is held, release it once before it engages again.
- The reset button moves both arms back to the rest pose. The move avoids self-collision when `KinematicsConfig.self_collision` is on, and otherwise stays within joint limits.
- In box mode, turning box mode on engages the pair, led by `box_lead_hand`. From a frozen pair, a single grip engages both arms again, and that controller leads.

### Re-engaging

When a grip re-engages an arm after a freeze, a disengage, or someone moving the arm by hand, `reengage` decides which side moves:

- `"clutch"`: the arm stays put, and the controller's current pose becomes the new origin.
- `"ramp"`: the arm keeps the controller-to-arm mapping from its previous engage and blends to where that mapping puts the controller. The blend is paced by `reengage_ramp_speed`, takes at least `reengage_ramp_min_s`, and follows a moving hand.

The arm never moves on the engage frame itself. A return to rest or a DAgger sync drops the mapping (`IKWorker.reset()`, `clear_engage()`), so the next engage starts fresh in either mode. Engages inside box mode ignore `reengage`. Leaving box mode with `"ramp"` blends both arms back to the mapping from before box mode.

## Live settings

Some settings can change while a session runs, from the headset or the control panel: `box_mode`, the other box-mode settings marked live above, `reengage`, `hold_to_engage`, `position_multiplier`, `teleop_max_vel`, and the gripper torque limit on hardware. `almond_axol.teleop.live.LiveSettings` validates each request and passes it to `VRTeleopCore.set_live(key, value)`. Changes apply on the IK thread before the next frame, or while the session is idle, so the control panel can change them with no headset connected. See [Live session settings](/api/vr#live-session-settings) for the full list and the wire protocol.
