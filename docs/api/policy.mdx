title: "almond_axol.policy"

---

`run-policy --policy_type custom` and `collect-dagger --policy_type custom`
use the [custom policy interface](/api/policy-plan). The robot sends compressed,
time-aligned observations and references to its accepted plan and confirmed
dispatches. The endpoint returns absolute action plans; the robot controls
when their rows may execute.

See the [wire contract](/api/policy-plan) for the message schemas, scheduling,
continuation, reset and DAgger semantics, or [Run Your Own Policy](/operations/custom-policy)
for robot-side configuration.

## Robot-side API

`PlanPolicyClient` provides the serialized WebSocket request/reply transport.
The CLI also uses a local scheduler to retain an accepted plan, reject expired
rows and invalidate pending replies when control ownership changes.

```python
from almond_axol.policy import (
    CameraSpec,
    Continuation,
    LastDispatched,
    PlanActions,
    PlanObservation,
    PlanPolicyClient,
    PlanSpec,
)
```

| Type | Purpose |
|---|---|
| `PlanSpec` | Ordered state/action layouts, cameras, control rate, horizon and scheduling contract |
| `PlanObservation` | Timestamped measured state, RGB images and continuation/dispatch references |
| `Continuation` | Accepted prediction identifier and first remaining row |
| `LastDispatched` | Published row whose local send completed in the current generation |
| `PlanActions` | Reply identifier, action matrix and optional tighter adoption deadline |
| `PlanPolicyClient` | Connect, reset, infer and close operations; inference and reset share one owner |

## Migration from the original custom-policy SDK

The robot commands now require the plan contract, identified by
`protocol: "axol-policy"` and `version: 2` in the handshake. There is no
legacy robot mode or automatic fallback.

Remove the former `--custom_protocol` CLI option and `custom_protocol` config
entries: that selector no longer exists. `--policy_type custom` always uses
the current interface. Wire version 2 is the compatibility marker, not an
opt-in setting; endpoints advertising version 1 must upgrade before connecting.

The original `Policy`, `PolicySpec`, `Observation`, `PolicyServer` and
`serve()` APIs speak the earlier raw-observation protocol. Their existing
server implementations are **not compatible** with the current robot
commands. Those standalone SDK APIs remain available for existing external
callers, but neither robot command selects them. An endpoint must implement
the [current contract](/api/policy-plan),
including exact setup negotiation, reset acknowledgments, compressed sensor
observations and published-plan references. Model loading and instruction
selection belong to that endpoint; the robot no longer forwards `policy_path`
or task instructions to it.
