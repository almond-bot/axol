Secure WebSocket server (WSS) that receives `VRFrame` JSON messages from the VR app. On first use it generates a self-signed TLS certificate in `~/.almond/vr/certs/`. You can use this module on its own to read raw VR data without full teleoperation, for example in a custom control loop or for data collection.

```python
from almond_axol.vr import VRServer, VRServerConfig
```

```python
import asyncio
from almond_axol.vr import VRServer, VRServerConfig

async def main():
    async with VRServer(VRServerConfig(port=8000)) as vr:
        while True:
            frame = vr.get_frame()
            if frame is not None:
                print(frame.l_ee, frame.r_ee)
            await asyncio.sleep(0.01)

asyncio.run(main())
```

Or use a callback instead of polling:

```python
def on_frame(frame):
    print(frame.l_grip, frame.r_grip)

async with VRServer() as vr:
    vr.set_on_frame(on_frame)
    await asyncio.sleep(float("inf"))
```

## `VRFrame` fields

### Controller input

| Field | Type | Description |
|---|---|---|
| `l_ee` / `r_ee` | `VRPose` | 6-DOF end-effector pose (position and quaternion). |
| `l_elbow` / `r_elbow` | `VRPosition` | 3D elbow positions. |
| `l_grip` / `r_grip` | `float [0, 1]` | Gripper commands. `0` is closed and `1` is open. |
| `l_lock` / `r_lock` | `bool` | Grip button states. See [Engage behavior](/api/teleop#engage-behavior). |
| `l_tracked` / `r_tracked` | `bool` | Whether the headset can see the controller. `False` frames are estimated, so the pose smoother skips them and holds the last good pose. Defaults to `True`. |
| `reset` | `bool` | A rising edge starts a return to rest. |
| `state` | `VRState` | `TELEOP`, `DATA_COLLECTION` or `RECORDING`, set by the headset. `SAVING` and `ERROR` are only pushed by the server. |
| `l_stick_x` / `l_stick_y` | `float [-1, 1]` | Left thumbstick (right is `+1`, forward is `-1`). Drives [Jelly](/guides/vr-interface#jelly)'s translation when one is configured. |
| `r_stick_x` | `float [-1, 1]` | Right thumbstick x (right is `+1`). Drives Jelly's rotation. |
| `r_stick_y` | `float [-1, 1]` | Right thumbstick y (forward is `-1`). Used only in [box mode](/guides/vr-interface#box-mode), where it moves the elbows. |
| `l_stick_click` / `r_stick_click` | `bool` | Thumbstick press. Left lowers Jelly's lift and right raises it. See the notes below for box mode. |

In box mode, while a grip leads the pair, a single click of either thumbstick toggles the grasp (`box_grasp`). With the pair frozen, the thumbsticks drive Jelly as usual. Pressing both thumbsticks together, within about 0.35 s, toggles box mode. The headset sends that toggle as a `set` message, described under [Live session settings](#live-session-settings).

The stick, click and `l_tracked` / `r_tracked` fields have neutral defaults, so a client that leaves them out still works.

### Timing and pose source

| Field | Type | Description |
|---|---|---|
| `t` | `float \| None` | Client capture time in ms (`performance.now()`), used by the pose interpolator. With `None`, the newest frame wins. |
| `seq` | `int \| None` | Frame counter set by the producer. With `pose_source_id`, it drops duplicate copies of a frame that arrive over different transports. |
| `t_host` | `float \| None` | When the poses were captured, on the host's `perf_counter` clock. The server fills it in from `t`. Mantis recordings align dataset rows to it. |
| `pose_source_id` | `str \| None` | Stable ID of the producer, shared across its transports and reconnects. |
| `pose_source_kind` | `"webxr" \| "tracker" \| None` | `webxr` for a Quest, `tracker` for a Lighthouse or Ultimate bridge. |
| `l_pose_profile` / `r_pose_profile` | `str \| None` | WebXR input profile of each Quest controller, such as `oculus-touch-v3`. Quest calibration is stored per profile. |
| `l_pose_space` / `r_pose_space` | `"grip" \| "target-ray" \| None` | Which WebXR pose each Quest controller reports. Production Mantis needs the calibrated `grip` pose. |

### Mantis episode control

| Field | Type | Description |
|---|---|---|
| `l_trigger_live` / `r_trigger_live` | `bool` | Whether each Mantis trigger node is still sending input. When it stops, the take fails its quality check. Defaults to `True`. |
| `episode_outcome` | `VREpisodeOutcome \| None` | One-frame `success` or `failure` signal from a trigger gesture. The outcome is logged but not saved in the dataset. |
| `episode_end_t_host` | `float \| None` | Host time at which a saved episode should end. The tracker bridge sets it to the start of the end gesture, so the trigger clicks are trimmed from the take. |
| `lock_release_id` | `int \| None` | Handshake ID for tracker bridges. The teleop core echoes it once it has handled a grip release. |

### Set by the server

The headset never sets these. The teleop core adds them to the frame it forwards to the IK worker.

| Field | Type | Description |
|---|---|---|
| `box_leader` | `"left" \| "right" \| None` | Which controller leads the pair in box mode. |
| `reengage` | `"clutch" \| "ramp" \| None` | The session's [re-engage behavior](/api/teleop#re-engaging). |

### Pose transports and USB/Wi-Fi fallback

The headset can stream poses over up to three transports at once:

- the network WebSocket,
- a USB `adb reverse` tunnel ([Quest over USB](/guides/quest-over-usb)),
- a WebRTC data channel ([remote teleop](/guides/remote-teleop)).

Every copy carries the same `pose_source_id` and `seq`, and the server handles each frame once, from whichever link delivers it first. If the cable drops, the Wi-Fi copy takes over with no reconnect. A late copy never rewinds the controls. The server forgets a producer's sequence when its last connection closes and on `disable()`, so a reloaded client starts fresh.

Only one producer controls the robot at a time. Other clients stay connected and still receive video, HUD state and the robot model, but the server ignores their frames and HUD controls.

- **Managed Quest Mantis** sets `VRServerConfig.pose_source_kind="webxr"`.
- **Managed Lighthouse or Ultimate Mantis** sets it to `"tracker"`, and gives the bridge and server a one-run `expected_pose_source_id`.
- **Without a pose source policy**, the first producer takes control. A tracker bridge can take over from a Quest. Once a tracker has control, the server doesn't fall back to a connected Quest if the bridge stops.

A Lighthouse or Ultimate world isn't registered to the Quest's floor, so the headset hides the 3D robot overlay by default in those sessions.

The WebRTC data channel (`almond_axol.vr.control_channel`) uses the same ICE and TURN path as the camera video, so an operator outside your tailnet can drive through a relay. Set the TURN server with `AXOL_TURN_URL`, `AXOL_TURN_USERNAME` and `AXOL_TURN_PASSWORD`. On a LAN or plain tailnet, leave them unset. If the data channel fails or drops, the headset requests it again after a delay.

## Server to headset feedback

The server pushes JSON messages to the headset over the same socket.

| Message | When | Effect |
|---|---|---|
| `{"type": "state", "value": "saving"}` | While an episode is saved | Blocks the recording controls. |
| `{"type": "state", "value": "error"}` | On an error | Shows an error indicator. |
| `{"type": "state", "value": "data_collection"}` | After saving | Turns the recording controls back on. |
| `{"type": "mode", "value": "teleop" \| "data_collection"}` | On connect | Locks the HUD to one mode. `teleop` hides the recording controls. |
| `{"type": "pose_source_kind", "value": ...}` | On connect | In a tracker-owned session, makes a Quest's recording controls view-only. |
| `{"type": "episode", "value": N}` | At each episode start | Shows **Episode N** on the HUD. |
| `{"type": "tracking", "value": true \| false}` | When tracking engages or disengages | The headset lets you move and resize camera screens only while tracking is off. |
| `{"type": "joints", "value": {...}}` | About 20 times a second | Arm joint state for the HUD. |

Send any of these with `VRServer.broadcast_text()`. `AxolVRTeleop.send_feedback_state(state)` sends the `state` message for any `VRState`.

`VRServer.set_mode()` sets the mode message. [`axol teleop`](/cli/teleop) sends `teleop`, and [`axol collect-data`](/cli/collect-data) sends `data_collection`. `AxolVRTeleop.send_feedback_episode(episode)` stores the episode number with `VRServer.set_episode()` and broadcasts it. Plain teleop never sets an episode, so the HUD hides it. The server sends the mode, pose source kind and episode to each client when it connects, so a headset that joins mid-session is up to date.

The `joints` message has this shape:

```json
{
  "type": "joints",
  "value": {
    "q": {"<urdf joint>": 0.0},
    "l_grip": 0.0,
    "r_grip": 0.0,
    "engaged": false,
    "pair": {"aligned": false, "width": 0.3, "tilt": 0.0, "grasp": "straight"}
  }
}
```

- `q` holds measured joint positions in radians when the robot reports them, and commanded targets otherwise. `l_grip` and `r_grip` run from `0` to `1`.
- `pair` is the gripper pair geometry from `IKWorker.pair_status()`, or `null`.
  - `aligned` is true when the grippers already form a box-mode pair. The **Box** button then reads *(aligned)*, since switching to [box mode](/guides/vr-interface#box-mode) needs no blend.
  - `width` is the grip width in metres, between the contact faces.
  - `tilt` is the pair's inward tilt in degrees, and `grasp` is `"flush"` or `"straight"`.

The server also serves the robot model under `/urdf/` (`axol.urdf` and `meshes/*.stl`).

### Live session settings

Some settings can change during a session from any client: the headset HUD, the control panel or the SDK. They are defined in `almond_axol.teleop.live.LiveSettings` and use three messages on the same socket.

- **Client to server:** `{"type": "set", "key": "<key>", "value": <value>}`. The callback set with `VRServer.set_on_setting()` handles it. The value is checked for type, range and choices, and a rejected request is logged and not echoed. A boolean key also accepts `"value": "toggle"`, which flips the server's current value.
- **Client to server:** `{"type": "session-config-request"}`. The server re-sends that client the session config it sends on connect: `mode`, `settings`, `pose_source_kind`, `pose_mode`, `tracking`, `episode` and `hud`. Send it once your message listeners are ready, so you don't miss the copy sent on connect.
- **Server to clients:** `{"type": "settings", "value": {"schema": [...], "values": {"<key>": ...}}}`. Sent on connect, on `session-config-request`, and after every `set`, so all clients show the server's state. Each `schema` entry has `key`, `label`, `type` (`"boolean"`, `"select"` or `"number"`), `help`, `options`, `min`, `max`, `step` and `unit`. Both UIs build their controls from it.

| Key | Label | Type | Effect |
|-----|-------|------|--------|
| `box_mode` | **Box mode** | boolean | Turns box mode on or off through `VRTeleopCore.set_box_mode()`. |
| `box_lead_hand` | **Box lead hand** | `"right"` / `"left"` | Which controller leads when box mode turns on. |
| `box_grasp` | **Box grasp** | `"straight"` / `"flush"` | Fingers straight forward, or turned inward onto the box. A live pair blends to the new grasp. |
| `box_flush_deg` | **Angled yaw** | number, ° | How far the `flush` grasp turns each gripper inward. Applies at the next engage or grasp switch. |
| `box_face_left` / `box_face_right` | **Left face** / **Right face** | `"auto"` / `"+x"` / `"-x"` | Which side of each gripper faces the box. Applies at the next engage. |
| `box_elbow_out` | **Elbows out** | number, ° | How far out the elbows are held in box mode. |
| `box_squeeze_force` | **Squeeze force** | number, N | Cap on each arm's clamp force. Hardware only. |
| `box_squeeze_lean` | **Squeeze lean** | number, × | Scale on the inward lean as the clamp builds. Hardware only. |
| `box_squeeze_trim` | **Squeeze trim** | number, ° | Most extra inward yaw the trim may add. Hardware only. |
| `box_squeeze_torque` | **Squeeze cap** | number, Nm | Hard shoulder torque cap in box mode. Hardware only. |
| `reengage` | **Re-engage** | `"clutch"` / `"ramp"` | Calls `VRTeleopCore.set_reengage()`. Applies at the next grip press. |
| `hold_to_engage` | **Hold to engage** | boolean | Grips act as per-arm dead-man switches instead of toggles. |
| `gripper_torque` | **Grip force** | number, Nm | Torque limit of both grippers. Hardware only, so it is hidden in sim. |
| `position_multiplier` | **Reach scale** | number, × | Scale from hand motion to arm motion. |
| `teleop_max_vel` | **Arm speed** | number, rev/s | Joint velocity cap while tracking. |

See [`VRTeleopConfig` fields](/api/teleop#box-mode) for what each box-mode setting does. The `box_*` keys exist only when the robot has the parcel gripper (`VRTeleopConfig.gripper == "parcel"`). Otherwise they are left out of `schema` and `values`, and a `set` of one is rejected. Clients show box mode only when `box_mode` is in `values`.

`VRTeleopCore.set_live()` queues each change and applies it on the IK thread before the next frame, or while the session is idle. Settings that the IK worker reads are passed on to it as `("set", key, value)` messages.

The server also relays HUD state between clients. The active Quest publishes its save or discard confirmation and the recording countdown as `{"type": "hud", "value": {...}}`. The server forwards the latest value to every other client, re-sends it to a client that joins mid-dialog, and clears it when the publisher disconnects. Viewers and Quests in tracker-owned sessions can't publish HUD state. The control panel uses this relay to show the headset's popups.

## Camera video to the headset

The server can stream camera frames to the headset over WebRTC. Register a source per camera with `set_video_sources()`:

```python
vr.set_video_sources({
    "overhead":  overhead_cam,
    "left_arm":  left_cam,
    "right_arm": right_cam,
})
```

A source can be:

- a pre-encoded camera from the GPU pipeline (`gst_zed`), with `subscribe()` and `alive`. Its H.264 frames go straight to the headset with no encoding in Python.
- a connected `ZedCamera` or stereo eye, which the relay adapts.
- any object with fixed `width`, `height` and `fps`, and `wait_next(after_ts, timeout_ms)`.

Pass `None` or `{}` to turn video off. [`axol teleop --cameras`](/cli/teleop) and [`collect-data`](/cli/collect-data) set this up for you.

Signaling uses the existing `/ws` channel, so no extra ports are needed. The headset sends `webrtc-request`, the server replies with a `webrtc-offer` that has one video track per camera, and the headset answers with `webrtc-answer`.

- A stereo overhead camera streams both eyes side by side in one track, `overhead_sbs`, which the VR app shows per eye. Without GStreamer, the SDK fallback sends two tracks, `overhead_left` and `overhead_right`.
- A stereo wrist camera streams one feed under its slot name, like a mono camera.
- Dataset recording still stores both eyes of a stereo overhead camera as two observation keys.

### Pipeline

Teleop and data collection share one camera path that stays on the GPU (`almond_axol.video.gst_zed`). The zed-gstreamer sources (`zedxonesrc` for mono, `zedsrc` for stereo) capture into GPU memory, and one GStreamer pipeline splits each frame into up to three branches:

- **Headset:** 30 fps, encoded by NVENC (`nvv4l2h264enc`). aiortc forwards the H.264 packets to the headset without re-encoding.
- **Dataset:** paced to the recording fps, downscaled and NVENC-encoded. Each frame keeps its exposure timestamp, so the recorder can pair it with the nearest robot state without copying or re-encoding the frame.
- **Raw:** converted to RGBA for policies and for the fallback path. Its exposure timestamps are also on the `time.perf_counter` clock.

Camera capture, encoding and WebRTC run in a separate process (`almond_axol.video.video_proc.VideoRelayProcess`), registered with `set_video_manager()`. Teleop builds only the headset branch. Data collection adds the dataset branch and a recorder process that owns the `LeRobotDataset`.

During collection, the recorder pairs each frame set with the robot state sampled nearest the median camera exposure. It discards the episode instead of saving a mismatched row if any of these happen:

- a timestamp is missing,
- a frame is stale or repeated,
- the cameras and robot state are too far apart in time,
- the predictive video stream breaks.

If shared-memory frame transport isn't available, collection falls back to raw frames. If the patched ZED plugin can't be verified, it falls back to the ZED SDK.

This path needs the GPU camera stack that the host installer sets up:

- GStreamer and PyGObject from [`axol gst.install`](/cli/gst-install).
- The patched zed-gstreamer plugins from [`axol gst.build-zed`](/cli/gst-build-zed). The NVENC elements come with the Jetson L4T BSP.
- NVENC and VIC clocks pinned to their maximum. [`axol provision`](/cli/provision) does this (see [`jetson.setup`](/cli/jetson-setup)), and the installer's systemd unit reapplies it at boot. Without it, encode latency per frame roughly triples.

## `VRServerConfig` fields

| Field | Default | Description |
|---|---|---|
| `port` | `8000` | WSS listen port. |
| `certfile` | auto | Path to the TLS certificate. `None` uses the generated certificate. |
| `keyfile` | auto | Path to the TLS private key. |
| `pose_source_kind` | `None` | Which kind of producer may control the robot: `"webxr"` (Quest Mantis) or `"tracker"` (Lighthouse or Ultimate). Other clients stay connected as viewers. |
| `expected_pose_source_id` | `None` | The one producer ID allowed to control the robot. Managed Lighthouse and Ultimate sessions set it to a one-run token. |
| `interp_enabled` | `True` | Turns on the playout buffer, which uses the headset timestamp `t` to smooth uneven frame arrival. |
| `interp_min_delay_s` | `0.0` | Shortest playout delay, in seconds. |
| `interp_max_delay_s` | `0.15` | Longest playout delay, in seconds. The buffer adds delay only while frames arrive in bursts. |
| `interp_smooth_window_s` | `0.12` | Width of the smoothing window around the playout point. It adds half its width in latency. `0` turns it off. |
| `interp_outlier_k` | `4.0` | Outlier threshold for rejecting tracking glitches, in robust standard deviations. Lower rejects more. `0` or less turns it off. |
| `interp_max_lag_s` | `0.5` | Frames later than this are not played, but their grip and reset buttons still count. After a network stall the arms hold, then follow the current pose. `0` or less turns it off. |

<Warning>
  Before opening the VR app, accept the self-signed certificate by navigating to `https://<hostname>.local:8000` in the VR browser and proceeding past the security warning.
</Warning>
